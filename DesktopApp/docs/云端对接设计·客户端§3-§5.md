## 1. 权威契约回顾（桌面端对接口径）

### 1.1 REST（复用 `Cloud::Call`，自动带 Bearer + 401 自动刷新）

**§4 公共专栏 `routes/columns.js`**
| 方法 | 路径 | 说明 | 关键响应 |
|---|---|---|---|
| GET | `/columns` | 列表+分区 | `{ sections:[{id,name,desc}], posts:[{id,section,title,body,author,authorName,likes,liked,comments:[{id,user,text,ts}],createdAt,updatedAt}] }` |
| POST | `/columns` | 发布 | body `{section,title,body}` → 新建 post |
| GET | `/columns/:id` | 详情 | 含 `body` 与 `comments` |
| PUT | `/columns/:id` | 编辑（仅作者，否则 403） | body `{title?,body?}` |
| DELETE | `/columns/:id` | 删除（仅作者） | `{ok}` |
| POST | `/columns/:id/like` | 点赞切换 | `{ok,on,count}` |
| POST | `/columns/:id/comment` | 评论 | body `{text}` → `{ok,count}` |

**§5 媒体库 `routes/media.js`**
| 方法 | 路径 | 说明 | 关键响应 |
|---|---|---|---|
| GET | `/media/list` | 列表 | `{ items:[{id,kind,title,note,filename,size,url,createdAt}], canUpload:bool }` |
| POST | `/media/upload` | 上传 | **raw 二进制 body** + 请求头 `X-Meta: <base64(JSON {kind,title,note,filename})>` → `{ok,id,url}` |
| GET | `/media/file/:id` | 取文件 | 二进制原文 |
| DELETE | `/media/:id` | 删除 | `{ok}` |

- `KINDS`：`videos` / `music` / `images`（按扩展名白名单）。
- 白名单：`canUpload = whitelist.includes(user.name)`；默认 `[DEMO_USER]`（演示账户 `demo` 可上传）。

### 1.2 WebSocket（新建 `Realtime` 客户端，同端口同源，连上先发 `auth`）

上行：`auth` / `rooms:list` / `room:create` / `room:join` / `room:leave` / `room:admin` / `presence` / `chat:msg` / `chat:history` / `music:list`
下行：`auth:ok` / `auth:err` / `rooms:list` / `room:joined` / `room:error` / `presence` / `chat:msg` / `chat:history` / `music:meta` / `col:changed`

| 方向 | type | 字段 |
|---|---|---|
| ↑ | `auth` | `{token:"<accessToken>"}`（连接后第一帧） |
| ↑ | `room:join` | `{room:"public"｜"silent"｜"sprint"}` 或 `{code:"XXXXXX"}` |
| ↑ | `room:leave` | — |
| ↑ | `presence` | `{status:"online"｜"room"｜"focus", focusContent?, focusSeconds?}` |
| ↑ | `chat:msg` | `{text}`（`silent` 房拒绝，回 `room:error`） |
| ↑ | `chat:history` | — |
| ↑ | `music:list` | — |
| ↓ | `auth:ok` | `{user:{uid,username,...}}` |
| ↓ | `auth:err` | `{msg}`（令牌无效/过期 → 触发刷新并重连） |
| ↓ | `rooms:list` | `{rooms:[{id,name,desc,builtin,muted,count,code?,hasPwd?,max?,creator?,mine?,daysLeft?}]}` |
| ↓ | `room:joined` | `{room:{id,name,code,builtin,muted,mine}}` |
| ↓ | `presence` | `{room, members:[{uid,name,status,focusContent,focusSeconds,since}], count}` |
| ↓ | `chat:msg` | `{room, msg:{id,user,uid,text,ts}}` |
| ↓ | `chat:history` | `{room, list:[...]}` |
| ↓ | `music:meta` | `{room, track}` |
| ↓ | `music:list` | `{tracks:[{id,title,url,size}]}`（来自 §5 `kind=music`） |
| ↓ | `col:changed` | `{reason?}` → 触发 `GET /columns` 重新拉取 |

- 内置公共房：`public`（可聊天）/ `silent`（静音，拒绝 `chat:msg`）/ `sprint`（冲刺）。
- `presence` 只广播给同房间连接。

## 2. 架构（与 §1+§2 同构，零新增第三方依赖）

```
            ┌─────────────┐  REST (WinHTTP 同步)        ┌──────────────────┐
 RoomView──►│  Cloud (扩) │──────── GET/POST /columns ──►│  Server/         │
 MediaView─►│ §4 §5 REST  │──────── GET/POST /media ───►│  §1 §2 §4 §5     │
 RoadmapView│             │  （复用 Call：Bearer+自动刷新）│                  │
            └─────────────┘                              │                  │
                    │ 端点+令牌来自同一处                  │  §3 实时网关      │
                    ▼                                    │  (gateway.js)    │
            ┌─────────────┐  WebSocket (手写 RFC6455)      │                  │
 RoomView──►│  Realtime   │◄──── auth/rooms/presence ─────►│  ws 同端口同源   │
 RoadmapView│ (新·单例)   │───── col:changed 推送 ─────────│                  │
            └─────────────┘                              └──────────────────┘
```

- **§4/§5 走 REST**：在 `Cloud` 上新增公开方法，内部复用私有 `Call()`（自动带令牌、401 自动 `RefreshToken` 重试一次），与现有 `SyncNow` 同一套信任链。
- **§3 走 WebSocket**：新增 `Realtime` 单例，后台线程持有 Winsock TCP 长连接（手写 RFC 6455 封帧）；连上先发 `auth`；下行消息分发到视图注册的回调。
- **端点与令牌单一来源**：`Realtime` 通过 `App` 注入的两个 `std::function` 取「端点」和「当前 access 令牌」（来自 `Cloud`），**不直接 include `Cloud.h`**，避免头文件环依赖。`Cloud::BindAccount` 在账户切换时调 `Realtime::Reconnect()`。

> **⚠️ 传输层更正（2026-08-04）**：本文初稿 §3.3 写「WinHTTP WebSocket 单例」，实装时发现本环境 `WinHttpWebSocketCompleteUpgrade` 恒定返回 `ERROR_WINHTTP_INVALID_SERVER_RESPONSE(12152)` —— 已用裸 TCP 复核服务端 101 回包与 `Sec-WebSocket-Accept` 完全合规，连微软官方示例逐字复刻（`tools/ws_min.cpp`）亦失败。**故 §3 实装改为手写 RFC 6455 over Winsock（`ws2_32`）+ CNG（`bcrypt` 做 SHA1/随机数）**，行为可控且与服务端 `Server/src/realtime/ws.js` 口径一致。下文所有「WinHTTP WS」相关描述以此为准。
>
### 2.1 线程安全（沿用既有范式）
- `Cloud::Call` / `Realtime` 收发都在**后台线程**。
- 回调里**不碰渲染**：只把数据写进视图自己的「受互斥锁保护的网络缓冲」+ 置 `std::atomic<bool> m_netDirty`。
- 视图 `Update()`（UI 线程）每帧 `if (m_netDirty.exchange(false)) Layout(...)` 重排 —— 与 `Cloud::ConsumePulled()` 同一套路。
- 离线/连接失败：`Realtime` 置 `m_connected=false` 并退避重连；视图**静默降级**到本地占位，不弹错、不卡界面。

### 3.3 `src/net/Realtime.h` + `Realtime.cpp`（#8，新增）
手写 RFC 6455 over Winsock 单例（**不 include `Cloud.h`**，零第三方依赖）：
```cpp
class Realtime {
public:
  static Realtime& Instance();
  void Init(std::function<net::Endpoint()> epProvider,
            std::function<std::string()> tokenProvider);   // App 注入，取端点+令牌
  void Shutdown();
  void Reconnect();                                         // 账户切换/令牌刷新后调用
  bool Connected() const;                                   // atomic

  // 视图注册/注销下行处理器（OnEnter 注册，OnLeave 注销）
  using Handler = std::function<void(const lj::json::JVal&)>;
  void On(const std::string& type, Handler cb);
  void Off(const std::string& type);

  // 上行便捷方法（内部 Send）
  void JoinRoom(const std::string& id);
  void LeaveRoom();
  void SendChat(const std::string& text);
  void SendPresence(const std::string& status, const std::string& focusContent, int focusSeconds);
  void RequestMusic();
  void SendRaw(const std::string& json);

private:
  void Thread();                 // 后台：连接→auth→收帧→分发；断线退避重连
  void Send(const lj::json::JVal& m);
  // Winsock TCP 句柄 + 收发（手写 RFC 6455 封帧：上行强制掩码，下行解服务端帧）
};
```
- 帧处理：上行客户端帧**必须加掩码**（RFC6455 客户端义务）；下行服务端帧不带掩码，按 `opcode` 解 `text`/`close`/ping；30s 心跳（发 ping / 回 pong）。
- `auth:err`（令牌过期）→ 经 `tokenProvider` 重新取（App 注入的 provider 内部会触发 `Cloud::RefreshToken`）→ 重连。
- `col:changed` 下行 → 分发到视图注册的 `col:changed` 处理器（RoadmapView 据此 `Cloud::GetColumns` 重拉）。

### 3.4 `src/core/App.cpp`（#10）

## 4. 三视图接入规格（留给视图层/并行客户端开发实现 UI，本文定义接入点）

### 4.1 `RoomView`（§3）
- `OnEnter`：`Realtime::Instance().JoinRoom("public")`（或用户选中的房）；注册 `presence`/`chat:msg`/`chat:history`/`music:meta` 处理器 → 写入受锁的 `m_members`/`m_chat`/`m_tracks` 缓冲 + 置 `m_netDirty`。
- 本地专注计时照旧（独立状态，不跨用户共享，与 WebApp 语义一致）；状态切换时 `Realtime::SendPresence("focus"/"room", ...)`。
- 聊天框：本地缓存最近 N 条，输入经 `Realtime::SendChat` 上行；`silent` 房显示「本房禁言」。
- 背景音乐：`music:list`/`music:meta` 取到曲目后由 XAudio2 播放（本地音频后端，不阻塞）。
- 离线：连接未建立时全部回退到现有本地占位，无提示。

### 4.2 `RoadmapView`（§4）
- `OnEnter`：`Cloud::RunAsync([this]{ auto r = Cloud::GetColumns(); 解析→m_cols 缓冲; m_netDirty=true; })`；注册 `col:changed` → 触发同样重拉。
- 本地「总线路图」作为**置顶第一篇专栏**保留；服务端 `posts` 按 `section` 归入对应分区渲染（轮播/横滑飞卡沿用 DOSSIER 母题）。
- 点赞/评论：点击 → `Cloud::LikeColumn/CommentColumn`（`RunAsync`）→ 用返回 `on/count` 原地更新。
- 离线：仅显示本地「总线路图」，不显示服务端 posts。

### 4.3 `MediaView`（§5）
- `OnEnter`：`Cloud::RunAsync([this]{ auto r = Cloud::GetMediaList(); 解析 items+canUpload → m_media 缓冲; m_netDirty=true; })`。
- 服务端 items 与本地 `assets/media` 扫描**并列展示**（分区：源视频/源音乐/图片）。
- `canUpload` 为真时显示「上传」入口（`GetOpenFileNameW` 选文件 → 读字节 → `Cloud::UploadMedia`），上传完重拉。
- 点击服务端条目：下载到临时文件 `ShellExecuteW` 打开，或直接用浏览器打开 `url`（保守先用浏览器/临时文件，避免内嵌解码依赖）。
- 离线：仅显示本地 `assets/media`。

## 5. 离线降级与边界（必须遵守）
- 服务端未开 / 断网 / 401→刷新仍失败：`Cloud` 与 `Realtime` 均置离线态，三视图静默回退本地，**不弹错误、不卡 UI**。
- `Realtime` 断线指数退避重连（上限 ~30s）；`Cloud` 防抖上推失败仅记日志。
- 令牌过期：`Cloud::Call` 自动刷新并重试；WS `auth:err` 经 provider 刷新后重连；刷新也失败则转离线。
- 上传白名单：非白名单用户 `canUpload=false`，隐藏上传入口（避免 403 噪音）。

## 7. 风险与待决
- **WebApp 旧协议**：`Server/` 是桌面端权威后端；WebApp 若也要接同后端需另做协议迁移（不在本任务范围）。
- **二进制体经 `std::string`**：含 `\0` 安全（用 `.size()`），但须确保不在中途当 C 串处理。
- **WS 掩码帧**：客户端上行必须掩码，下行不掩码 —— 与 `Server/src/realtime/ws.js` 的 RFC6455 实现对齐（已用 `tools/smoke.js` 的掩码客户端验证过服务端收帧）。
- **大文件上传**：`POST /media/upload` 为单次同步体，超大文件会阻塞后台线程；MVP 阶段限制单文件 ≤ 50MB，后续可改分块。
