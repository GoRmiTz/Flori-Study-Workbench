## 概念 14 · 轨道（Orbita）· 完整设计思考（经验沉淀 · 2026-08-16）

### 一、怎么想到这个母题（设计起点，先排雷再选型）
- 开新概念**第一步不是"画什么"，而是先回读 `AGENTS.md` 概念全景，把已被否决的形态逐一排除**，避免踩已知坑：概念4「织」(织锦隐喻无清晰实用价值)、墨脉(脉络)、年轮/树(生长·古老)、场/流体(失控)、弦(时序)、层积(方块+撞色+时序)、气脉(低密度+硬矩形)、失败①②③(被动渐变/失控流体/抽测小游戏)。可用"形态"空间其实很窄。
- 用户给的硬约束：非时序、高密度离散、自然圆形边界、信息可视化优先、零辉光、非大众化。需要找一个**既全新、又天然满足这些约束**的形态。
- 原子轨道的灵感：把"知识宇宙"隐喻成一颗原子——**中心核 + 放射扇区 + 同心壳层**。它：
  - 天然**圆形/放射边界**（满足自然边界，对冲气脉的硬矩形截断）；
  - 同心壳层 = 一个**带刻度标轴的径向坐标系**（L1→L8 难度层级，直接可读，满足"信息可视化优先"对坐标轴/数值刻度的要求），不是纯氛围；
  - 高密度离散**电子点**（每点一个考点），满足高密度离散；
  - 科学现代感（原子/轨道），非 SaaS、非古老有机、非时序；
  - 三通道着色复用概念12 数据着色豁免。
- 结论：它和概念10(拓扑网)/12(星砂点云)/13(晶簇晶体)形态都不同，是**结构化壳层＋放射扇区**的原子隐喻，被选为全新方向。

### 二、信息编码方案（图表本体先于动效）
- 色相 = 学科（8 扇区各一协调色相族）；
- 明暗 = 掌握度（暗→亮，复用概念10 单色明度层次）；
- 点大小 = 分值权重；
- **壳层 = 难度层级**（由内 L1 向外 L8 难度递增，环上标注 L1–L8 刻度标签）——这是本概念区别于星砂的关键：**把"难度"做成可读的径向坐标轴**，而不是只靠颜色；
- 细线 = 同扇区电子按方位连成的"电子轨道"（环），体现知识关联；
- 顶部 KPI + 悬停精确面板（学科/壳层/分值/难度/掌握度/关联）。

### 三、怎么实现（确定性、headless 可验证）
- **渲染**：Canvas2D 主舞台 + 亮色纸感径向渐变（刻意不用 WebGL，规避黑屏风险；守"不黑屏"铁律）。
- **旋转**：四元数 trackball（继承晶簇 v1.2 已验证方案）。拖拽轴 = (dy, dx, 0)，增量四元数前置乘，定义在屏幕空间 → **无论转到哪个角度都"拖哪跟哪"**，彻底消除"有时反向"。
- **投影**：`project()` 必须回写 `sc/depth`（晶簇 v1.3 的**根因教训**：曾因不回写 depth 导致半径恒为 0、晶体隐形，误判为样式 bug）。电子点半径 `pointR(f)=(3.0+score*1.15)*f.sc*zoom*0.96`，**断言半径>0.5 才可见**——这是每次新形态都必须做的回归断言。
- **三通道着色**：`hsl(hue, sat(diff), light(mast))`，sat 随难度升、light 随掌握度升；零辉光（普通 alpha，无加性 bloom）。
- **动效（真实操作驱动/确定可控/非游戏/零辉光）**：
  - 旋转惯性落座（见 v1.1 修复）；
  - 滚轮缩放有界 [0.5, 2.2]；
  - 悬停高亮 + 精确面板；
  - 单击点亮 → **电子跃迁火花**（确定性平涂小菱形 + 阻尼下落，非辉光粒子）+ 邻点受控脉冲（阻尼收敛）；
  - **能量流**：亮点沿电子轨道按 `(tt+seed[i])%1` 周期性流动，体现"知识在传导"；
  - 静置 3s 自动演示（交互即停，非 idle 空浮）；
  - 右上角学科筛选 chips（点筛选高亮该扇区、其余压暗）。

### 四、校验清单（交付前必跑）
- `node --check` 语法；
- 独立数学测试：电子点半径 minR>0.5（可见）、各旋转/缩放态 NaN=0、trackball 方向（拖右→右移/拖上→上移）、壳层 L1–L8 标签 NaN=0、2000 次随机拖拽 NaN=0、惯性收敛；

- 探针 `window.__probe()` 回传 `{total,lit,nan,minR,maxR,pointsVisible,zoom,zoomBounded,autoOn}`。

### 五、v1.1 修复：拖拽轻微滑动即大幅跳跃（根因级）
- **现象**：用户"稍微滑动一下，就会有一个很大的跳跃，总是不能让轨道停在我想要的地方"。
- **根因**（读代码确诊，不靠猜）：释放后的惯性（momentum）写死了**固定角速度 0.12 rad/帧**（与拖拽实际速度/方向无关），按 0.9 衰减 → 累计约 **69° 的额外旋转**，且幅度失控。轻滑 5px 也吃满这 69°，所以"停不下来"。
- **修法**：惯性改为**与实际拖拽速度成正比 + 封顶 + 更快收敛**：
  - 拖拽时记录 `spinAng=min(0.05, sqrt(dx²+dy²)*0.006)`、`spinAxis=[dy/len,dx/len,0]`（轴仍跟手）；
  - 释放后每帧 `q=qNorm(qMul(qAxis(spinAxis,spinAng),q)); spinAng*=0.82`；
  - 于是轻滑→小幅旋转+小幅惯性→**几乎即停**；快速甩→按比例多转，确定可控。
- **验证**：5px 轻滑总旋转由 **70° → 11°**，且与拖拽距离成正比（3px≈7°、15px≈21°、50px≈33°）；`node --check` 通过。
- **经验（已写进 skill 正例 + 用户铁律㉗）**：旋转/惯性手感是"确定可控"的硬指标——惯性角速度**必须**来自真实拖拽速度、封顶、快速收敛，绝不能写死固定值；否则轻滑即暴冲，违背"确定可控"。
