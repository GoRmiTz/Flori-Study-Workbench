# 识墟 · 知识浮城 · 动效概念介绍

> 概念 23｜单 canvas 纯 Canvas2D｜回应「重开新档」要求，并吸取识渊（22）真机连续空白的教训：彻底放弃 WebGL2 / 多 canvas，改用最可靠的技术底座。

## 一、隐喻与母题

你不是「旋转一个物体」，而是**在一片漂浮的知识群岛之间连续穿行**。

- **浮岛 = 学科**：空间中散布 8 座不规则、半透明的「浮岛」，每座对应一个学科。岛与岛之间有距离，互不重叠。
- **岛上的光点 = 考点**：每座岛内部悬浮 22 个考点节点，明度编码掌握度、青绿描边标薄弱。
- **岛间的细线 = 依赖脉络**：跨岛存在前置/后继关系，构成可追踪的知识链路。

这是「漂浮聚落 /  archipelago（群岛）」语言——**不是点-线-环-星，不是中心旋转单体，不是方块堆叠**，是全新的空间母题。

## 二、为什么这次「必然能显示」

识渊（22）的教训：WebGL2 着色器真实编译失败 + 多 canvas 上下文冲突，导致真实浏览器连续两次全黑；而 headless DOM 桩因跳过真实 GLSL 编译、未复现 canvas 冲突而误报「全过」。

识墟改用 **单个 `<canvas>` + 纯 Canvas2D**：

- 没有 WebGL → 没有 GLSL 编译黑盒；
- 没有第二个 canvas → 没有「webgl 上下文占用后取 2d 得 null」的崩溃；
- 透视 3D 由 JS 手动投影实现（相机基向量 + 透视除法），所有浏览器都支持 Canvas2D。

**结论**：只要浏览器支持 Canvas2D（几乎所有现代浏览器都支持），就必显示。headless 校验也因无 GLSL 黑盒而真正可执行（逻辑层真跑），不再有「桩过了真机空」的盲区。

## 三、信息编码（守红线 · 拒绝彩圆俗套）

| 维度 | 编码方式 |
| --- | --- |
| 学科 | 空间位置（浮岛分布），非颜色 |
| 掌握度 | 节点明度（亮=已掌握，暗=薄弱） |
| 薄弱点 | 青绿描边小环标记（非彩圆填充） |
| 依赖强度 | 线条透明度 + 线宽 |
| 节点形态 | **菱形**（细结构几何，禁实心彩圆，铁律㉘） |

配色：单主色墨青（`hsl(192,30%,L%)`）+ 青绿强调（`#2fa », 47,174,155`）+ 深底，零辉光、克制。

## 四、交互（舒服 · 无长跳 · 游戏化探索）

| 操作 | 行为 | 对应铁律 |
| --- | --- | --- |
| 拖拽 | 轨道环视（yaw/pitch，∝真实拖速，无反向） | ㉚ 真三维轨道 |
| 滚轮 | 连续推进 / 拉远（lerp 缓动 0.12，**无长跳**） | ㉛ 步距连续 |
| 悬停 | 衬线排版浮层读出学科 / 掌握度 / 难度 / 薄弱 | ㉚ 二维浮层 |
| 点击 | 锁定该考点 + **相机平滑飞入其浮岛** + 高亮前置链 | ㉜ 探索乐趣 |
| Esc | 复位视角 | — |
| HUD | 顶部衬线标题 + 已探索 X / 176 进度（无计分） | ㉜ 禁廉价小游戏感 |

「飞入浮岛 + 高亮前置依赖链」是**探索式游戏化**：你在 3D 结构里「走通知识脉络」，没有抽测、没有输赢、没有排行榜。

## 五、资源做足（不再简陋）

- 8 学科 × 22 节点 = **176 节点 / 184 边**（含跨岛前置）；
- 浮岛壳用节点投影凸包半透明填充，给出「体 / 岛」的体块感，而非散点星图；
- 深度排序（画家算法）保证前后遮挡正确，有真实 3D 体积感。

## 六、诚实限制

- headless 已证：逻辑零崩溃、176 节点全部投影在屏内（不会全黑）、相机/投影数值无 NaN、拖拽/滚轮/悬停/点击/Esc 全程零异常。
- **观感项（浮岛密度、穿行手感、配色协调、衬线排版、薄弱标清晰度）仍须你在真实浏览器（Chrome/Edge 直接开本地文件）确认**。
