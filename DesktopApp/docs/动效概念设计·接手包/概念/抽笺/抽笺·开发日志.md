# 概念 27 · 抽笺·知识笺匣 · 开发日志

## 2026-08-18（二）

### 背景
用户核心批评（原话）："欠缺的主要是怎么在软件中利用上……怎么成为买点还是有欠缺，看起来像无用的花瓶"，并点名「抽卡」项目为正面范式——"用户可以通过卡片获取知识，且富有娱乐性"。
→ 据此新增 **铁律㉟（拒绝花瓶·必须有买点/价值闭环）**，写入 `用户审美偏好与动效铁律.md` 与接手包 `01_设计红线…md` 两处，并在 `AGENTS.md §3、§2.1` 同步（概念 27 全景行 + ㉟ 条目）。

### 设计决策
- 母题选**笺匣/签筒（求签仪式）**，直接对齐"抽卡范式"：通过卡片(笺)获取知识 + 富有娱乐性。
- 核心循环 = **抽 / 阅 / 收**：点笺匣抽一笺 → 墨韵揭示出考点 → 标「已会/待巩固」→ 飞入「已习笺册」并写回复盘/错题集。
- **买点显式化**：娱乐化随机复习（钩子）+ 装册进度可视化（留存）+ 待巩固加权重抽（自适应闭环）。
- **软件落点显式化**：笺面内容来自 F-D 练考 `QuizParser` 题目 `.md`；「已会」→ ReviewEngine、「待巩固」→ 错题集；顶栏 mock 真实 chrome。
- 交互范式 = 抽取-阅读-归档仪式流（固定取景），落实铁律㉞（非轨道观察）。

### 实现要点
- 单文件 HTML：Canvas2D 主舞台（透明底，自洽）+ WebGL2 受控背景（暖纸+淡墨晕+笺纹，失败即 CSS 纸纹兜底，绝不黑屏）。
- 14 条示例知识笺（行测/申论/专业），每条含 学科/考点名/精讲/真题引。
- 状态机：`idle → rise（墨韵揭示 560ms）→ read → archive（飞入笺册+盖章 560ms）/ discard（Esc 220ms）`。
- 暴露 `window.__api`（startDraw/mark/getProbe/setSize）供无头探针。

### 修复的 bug
1. `drawSlip` 在归档阶段忽视插值坐标 `slipX/slipY`，始终画在固定 `targetY` → 补全 `drawCX/drawCY` 并每帧从 `slipX/slipY` 同步，归档时笺片正确飞向笺册。

### 校验
- `node --check`：SYNTAX_OK。
- 双模式 DOM 桩无头探针（WebGL 可用 / WebGL=null）均 **ALL_PASS**：
  - init 不抛、ready；idle/onScreen>0、lightBg=true、colorfulCircles=0、nan=false。
  - 抽一笺 → phase=read、curId≠null；标「已会」→ collected+1、today+1、归档回 idle；标「待巩固」→ pending+1、today+1；循环二次抽仍 onScreen>0、nan=false。
- 关键结论：**WebGL 完全缺失时主舞台仍完整渲染（onScreen>0），黑屏死因结构性消除**。
