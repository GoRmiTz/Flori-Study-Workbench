## 概念 2 · 叠笺 DiéJiān —— 叠层卡片 / 钻取（本次）
- 日期：2026-08-16
- 全新隐喻（不重复砚心/墨脉）：一笺之下犹有千笺。每层知识点做成一叠实体笺卡，钻取时父层不退场、退成身后淡影（物理层叠呈现树深度）；翻开一张 → 下层笺卡自后层叠"发牌"而生。
- 动效语言（全部真实操作驱动、确定可控、无游戏机制）：
  - 悬停最前卡片 → 微抬 + 身后卡片向右探出（弹簧，非自动乱跑）；
  - 滚轮 / 拖拽 → 翻动同层笺卡，惯性阻尼必落座；
  - 点击最前卡片 → 展开下层考点，新笺自后层叠入场（弹簧 + 显隐回弹）；
  - 右键 / 返回 → 收束回上一层，淡影归位。
- 针对上一代"晃眼睛"的修正：配色收敛暖纸+墨灰+一点朱砂标签（无高对比闪烁）；自动演示放慢到 ~4.2s/步且被任意操作立即打断；运动全走低系数长缓动。
- 技术：纯 Canvas2D（杜绝 WebGL 黑屏风险）；DPR 自适应；启动延迟到 load+rAF 后测量尺寸（沿用墨脉 resize 兜底，避免默认 300×150）；弹簧系数用 `1-pow(k,dt)` 帧率无关。
- 文件：`docs/叠笺·动效概念原型.html`、`docs/叠笺·动效概念介绍.md`。
- 校验：JS 语法 node --check 通过。仍须浏览器目视确认观感（Chrome/Edge 直开本地文件最稳）。

## 概念 2·v2.1（切换重设计，同日晚）：拆包式层级切换
- 用户反馈：原"发牌/平推"式卡片切换太市场主流、不独特。要求改为：**点击层级卡 → 该卡逆时针倾斜约 15° 退到身后，其下层卡片叠在它之上**（拆完包装、把内卡放在包装上的感觉）。
- 实现：引入**持久父层残影（ghost）系统**，与当前层叠笺分离渲染。
  - `syncGhosts()` 按 history 维护 ghost 元素（drill 时在顶部新增、back 时顶部化开消散）；每个 ghost 持 `dVis`(连续深度)、`t`(0=正面被点的卡 / 1=退后姿态) 两枚弹簧。
  - `layout(dt)` 每帧：ghost 姿态 = lerp(正面居中, 逆时针-15°·下沉·缩小·压后, t)；depth d 越深退得越远（rot 约 -15°-(d-1)*5）。drill 时新 ghost 从 t=0 弹簧到 1 → 视觉即"被点卡倾身退后成包装"；原 ghost 的 dTarget+1 顺势再退一层。
  - 返回：顶层 ghost 置 `dying`，弹簧 `op→0` 同时放大 1.18 化开消散；也可点击任意残影 `goBackTo` 跳回该层。
  - deck 卡片改用 `cardEls.forEach(el=>el.remove())` 局部清除（不再 `innerHTML=''` 以免误删 ghost）。
  - 自动演示加入随机 drill，确保"拆包"转场在受限预览里也能看到。
- 文件：`docs/叠笺·动效概念原型.html`（重写 render→renderDeck+syncGhosts+makeGhost/goBackTo，layout 增 ghost 驱动）、`docs/叠笺·动效概念介绍.md`（钻取条目标注拆包式）、本日志追加 v2.1。
- 校验：node --check 通过；grep 确认无残留 `render()` 旧调用。仍须真机目视确认拆包动效观感。

## 概念 2·v3（根因重写，同日晚）：统一堆叠 / 无翻面 / 不穿模
- 用户最后反馈（且明确要求"自己发现问题并解决、不要靠提示词缓存打补丁、要稳定设计而非省 token"）：卡片仍和上级穿模；卡片翻阅的特效仍和上级卡重复，不好看。建议解法：不要分离卡片、不要翻动、叠在一起。
- **根因诊断（非数值补丁）**：v2.1/v2.2 的架构是"两套独立 3D 系统共存同一 perspective 空间"——当前层叠笺(deck) + 独立父层残影(ghost) + 一个 `.flipper` 的 rotateY 翻面。残影与 deck 各自 3D 变换，z 区间靠数值拉开维持不相交；任一动效（难/极卡 3D 倾斜、父层退后姿态）幅度略大即在中间区间穿插（穿模）。翻面 rotateY 动画 + ghost 自身 3D 姿态 → "卡片在翻"与"父卡在倾"两种动态同画并发（特效重复）。数值调参无法稳定。
- **v3 修法（拆双系统、统一单栈）**：
  1. 单一深度栈：所有卡（兄弟 + 祖先）同一 `Map` 的 `.card`，每帧朝 `poseForDepth(d)` 弹簧归位，`z=-Z*d`（Z=130，严格单调）→ 数学上不可能相交。
  2. 去掉翻面：末级卡不分正反、不 rotateY；题要印在卡面、单击展开浮层。删掉"翻"这个重复动效 + 一层 3D 状态。
  3. 特效只给最前卡：`.fx-spot/.fx-reflect/3D倾斜` 一律 `.card.front:hover` 门控，仅唯一最前卡亮；背后卡静默仅留常驻极淡流光描边。
  4. 背后卡只用 `rotateZ`（平面内）绝不离开自身 z 平面 → 无论怎么摆不与邻层穿插。
  5. 拆包叙事保留：父层退后是牌堆里"更深一层"的同一套弹簧，不是独立 ghost 系统。
- 关键常量：`Z=130, YS=CH*0.15, XS=CW*0.05, SS=0.05, RZ=4, OP=0.13, VIS=3`；`poseForDepth(d)={x:XS*d, y:YS*d, z:-Z*d, s:max(0.5,1-SS*d), rz:RZ*d, o:max(0.16,1-OP*d)}`；GRADE tilt 降至 极=8/难=7/中=0/易=0。`front` = 当前 `d=-cur.z/Z` 最小的卡，获 tilt+hover 提升，其余 `rotateZ` only。
- 文件：叠笺·动效概念原型.html（**整体重写**：移除 ghost/flipper/horizontal-deal，computeItems 统一堆叠、frame 单栈弹簧、makeCard 无翻面、drillInto/goBack 仅推/弹 history）、叠笺·动效概念介绍.md（整体改写为 v3，含根因诊断段）、本日志 v3。
- 校验：node --check 提取内联脚本 → **SYNTAX_OK**。仍须真机 GUI 目视确认：① 钻取时父层沉后、不再穿模；② 背后卡静默、特效不重复；③ 悬停最前卡倾斜/镜面/追光观感；④ 横向名片比例。

## 方法论总结（v1→v3.5 全程复盘）

> 目标：把"快速得到创意 → 实现创意 → 落地问题解决"沉淀为可复用流程，避免下次走弯路。

### 一、如何快速得到创意（Ideation）
1. 每次从零起一个"全新隐喻"，不与过往交付（砚心/墨脉）重复：先定"这个动效像什么"（叠层卡片=拆包/藏书），再定"落在哪个真实界面"（芙洛理的知识库/练考）。
2. 从被认可的美术参考里借语言、不抄效果：终末地（卡面稀有度/抽卡稀有感但非游戏）、明日方舟（HUD 准星/切角框/扫描揭幕）只借"视觉语汇"，落到考公场景要重新翻译。
3. 创意先在脑子里过一遍铁律四问：动效为主？非游戏？真实操作驱动？确定可控？落真实界面？非大众化？任一不过就换方向。
4. 用户给的方向往往只说"感觉"，要主动翻译成可实现的动力学（如"包裹感"→父层退后略放大；"拆包"→父层倾身退后成包装）。

### 二、如何实现创意（Implementation）
1. 原型优先、文档后写：先出能玩的 HTML/Canvas/CSS/WebGL，让用户亲手体验，不先写设计文档。
2. 物理用帧率无关弹簧：cur += (tgt-cur)*(1-pow(k,dt))，拖拽/滚动手感不受帧率影响。
3. 启动延迟到 load+rAF 再测尺寸（flex/绝对定位未 flush 时 getBoundingClientRect 拿到 300×150 默认值，整图挤左上角）。
4. WebGL 全程 try/catch + 着色器编译/链接校验，失败降级 CSS 纸纹，杜绝黑屏。
5. 交付前 node --check 校验内联 JS 语法；诚实说明 headless 无法验证观感，请用户在 Chrome/Edge 本地打开确认。

### 三、落地问题如何有效解决（Problem-Solving，避免弯路）
1. 根因优先、拒绝补丁：用户明确说过"不要靠提示词缓存打补丁、要稳定设计"。两处动效在同一空间打架（穿模）时，应"拆双系统、统一单栈"做架构级重写，而非调 z 数值——数值调参永远调不稳。
2. 效果重复 = 分层门控：某特效在多层同时出现（翻面+父层倾），把特效用 .card.front:hover 之类门控到"唯一最前卡"，背后卡静默。
3. 交互失效先看两件事：① 状态变量是否真被赋值（曾因 S.dragVel 从未赋值导致"拖很长不切换"）；② 事件是否真触发（曾因 CSS 缺 .aurora.on 规则导致光晕 opacity 恒 0、永远看不到）。
4. 单击/拖拽必须分离：按下即 dragging=true 会让单点误显拖动；用 6px 阈值判定，越阈才升级为拖拽。
5. 点击要语义命中：卡包/多对象场景，pointerup 用 hitCard(x,y) 命中谁开谁，别用"恒为聚焦对象"开包（曾点侧边考研却开考公）。
6. 层级回退别重复入栈：点上级背后卡应 goBackTo(histIndex) 回退，而非再 push 一层（曾现 行测/资料分析/行测/资料分析 重复层级）。
7. 背后卡要静止：兄弟深度用吸附后的 frontTarget 而非连续 scrollPos，拖拽时背后卡不动、仅最前卡跟手、松手吸附归位（消除"背后卡跟着动"）。
8. 防误操作从源头掐断：拖拽文字框选/开新标签是浏览器原生行为，靠 user-select:none + e.preventDefault() + 三层 dragstart 拦截双保险，不是事后清选区。
