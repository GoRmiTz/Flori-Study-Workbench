## 0. 给接手者的一句话

你接手的是一组**动效概念原型**（单文件 HTML，浏览器直接打开即玩）。目标是：在「动效为主、非游戏、由真实操作驱动、确定可控、落真实界面、非大众化」约束下，持续从零创新，直到某个方向被用户评审认可、可落地进 `DesktopApp/` C++ 客户端。

**目前一切都还是 `docs/` 原型阶段，未合并进 `App.cpp` / 任何视图 / 看板娘层。**

## 1. 模块定位与开发目标

| 项 | 内容 |
| --- | --- |
| **本质** | 探索性概念原型工厂：用单文件 HTML 快速验证「动效方向」，认可后再谈客户端集成。 |
| **目标** | 产出被用户认可、可落地的动效母题；当前已有两个被认可方向（见 §2）。 |
| **交付物** | 每个概念一个子文件夹，含「介绍 + 原型 + 开发日志」三件套（见 §6）。 |
| **非目标** | 不是生产代码、不是客户端功能、不是游戏。 |
| **集成远景** | 方向被最终认可后，进入「仅新增 `src/gfx/`」阶段（仍守客户端红线，见 §8）。 |

**最高优先级共识**：动效必须让数据 **直观可读**（信息可视化优先），不能为动效而动效；已认可版本勿在其上堆新风格层。

### 2.2 已认可方向（后续概念的基线，勿重做、可借鉴精神）

- **概念 10 考点星图 = 新基线配方**：非时序 + 单主色（墨青 #2f5a57→#6ee0c4 明暗层次）+ 明度层次编码掌握度 + 细线拓扑网（线粗=关联强度）+ 力导向确定性布局 + 顶部 KPI + 悬停精确面板 + 真实操作驱动（悬停高亮 / 点击掌握弹簧脉冲 / 拖拽平移缩放）。
- **概念 12 识海·星砂（v2 定格）**：高密度离散星点云（368 星 / 736 连线，确定性 LCG）+ 全幅深底自然边界 + 三通道数据着色（色相=学科 / 纯度=难度 / 明暗=掌握度，对单色基线的定向豁免）+ 正常考点卡+三按钮+rotateY 翻面+弹簧弹入+图谱收藏。V3→V5 持续加层均被否，**当前唯一基线就是 v2**。

### 2.3 负面对照（勿重做，仅作警示教材）

- **弦(8)**：信息可视化欠缺 → 铁律「信息可视化优先」。
- **层积(9)**：方块堆叠 + 撞色 + 时间轴 → 铁律「告别方块 / 配色克制 / 放弃时序」。
- **气脉(11)**：稀疏采样插值出大而空的场 + 硬长方形截断 → 铁律「高密度离散 / 自然边界」。
- **素履 V2–V5(7) / 复盘生长(5) / 失败①②③**：同一母题连否 2 次就换、勿在错母题打补丁、圆球辉光 cliché、古老有机形态（年轮/树）不够现代。

### 2.4 母题锁定警示（本轮新增·关键）
用户于概念 17 收尾时明确指出：**方向被固定住了，没达到创新，都是老元素**。复盘确认：概念 10 考点星图 / 12 识海星砂 / 13 晶簇 / 14 轨道 / 16 脉络 / 17 学仪，母题各异但**视觉语法高度雷同**——都是「节点/点阵 + 连线/细线 + 同心环/径向布局 + 星点云」的 2D 平面表达。这已构成**母题锁定**，违背「创新第一」（约束①）。

**应对（新增铁律㉙㉚）**：
- 禁止继续在「点-线-环-星」语法内打转；新概念必须尝试**全新空间母题**（实心 3D 体 / 流场 / 结构桁架 / 多面体 / 地貌 / 织体 等），且与已通过方向形态显著不同。
- 新概念须同时提供**真三维轨道交互**（透视投影 + 360° 拖拽旋转 + 缩放）与**二维浮层交互**（悬停探针 / 点击剖面 / KPI），3D 与 2D 协同。
- 概念 10/12 仍是「信息可视化 + 创新」的精神基线，但**形态上不再作为模仿对象**；后续一律从零探索新空间语法。

## 3. 设计铁律（红线速记）

> 全本与「用户历次反馈 → 提炼铁律」逐条溯源见 `01_设计红线_用户审美偏好与动效铁律.md`。此处为接手速记，动手前必逐条对照全本 §三 自检清单。

1. **创新第一、非大众化**：拒 SaaS 蓝白渐变+圆角卡片那套，要有辨识度与创意。
2. **有意义 + 实用价值优先**：不能为动效而动效；动效须服务「让颜色/图形/功能更直观」。
3. **现代感、艺术现代化**：弃用古老有机形态（年轮/树/生长）。
4. **克制、零辉光、零 bloom**：用色深/笔触/描边，不用加性光球；圆球辉光 cliché。
5. **【最高优先级】信息可视化优先、实用性优先**：数据须直观可读（坐标轴+数值刻度+标签+可读几何先于风格层）；交互要能直接获取信息（框选区间→实时聚合读数；悬停→精确单点值）。拒绝「好看但读不出数据」。
6. **真实操作驱动、确定可控、非游戏**：拒问答/计分/抽测/输赢；动力学须阻尼收敛，不失控乱跑、不 idle 空浮。
7. **落真实界面**：看得见加在哪（mock 真实 chrome / tabs）。
8. **图表本体 + 风格层分离；形态优先于特效；禁用软圆辉光作主特效**。
9. **先确认母题再动手**：同一母题连否 2 次就换路子，勿在错母题打补丁。
10. **每次都要总结用户反馈与想法**（协作习惯，见 §9）。
11. **形态美感优先、告别方块堆叠**：用细线/点阵/连续面/拓扑网，拒绝柱状/色块/方块堆叠。
12. **配色必须讲究（和谐、克制、有层次）**：单主色+灰度层次或协调类比色；维度靠明度/大小/位置区分，不靠撞色。
13. **放弃时间轴 / 时序母题**：转向空间关系网/结构平衡/知识拓扑/形态映射等非时序方向。
14. **【通过的配方即新基线】** 概念 10 配方作为后续新基线；概念 8/9/11 正式摒弃（仅 9 留作负面对照教材）。
15. **信息载体须高密度离散**：拒稀疏采样插值出「大而空」的场（气脉死因）；用密集点阵/细密线网/大量小单元。
16. **形态边界须自然**：拒硬长方形截断（气脉死因）；优先圆形/放射/有机/全幅深底漂浮。
17. **数据着色豁免**：仅当颜色系统性编码数据维度（概念 12 三通道）时允许多色相，仍守零辉光、每类协调色族。
18–25. 概念 12 卡片专项（抽卡稀有度光晕 / 去按钮交互动效 / 封面即封面 / 切角描边正常卡 / 翻转非旋转漂浮慢 / 封面=棱镜层去矢量 / 收藏面板常驻 / 多变换拆独立 DOM 层）——详见 `01_` 对应条目，**但概念 12 当前定格 v2，这些专项仅作历史经验，勿在 v2 上叠加**。
26. **【最重要】已认可版本勿堆新风格层；连续否定某方向时，优先回退到上一认可版，而非继续打补丁**（概念 12 v3→v5 连续三版加层即反面教材）。
29. **【突破母题锁定】禁止在「点-线-环-星」2D 词汇内打转**：概念 10 星图 / 12 星砂 / 13 晶簇 / 14 轨道 / 16 脉络 / 17 学仪 虽母题各异，却共用同一套 2D 平面视觉语法（节点/点阵 + 连线/细线 + 同心环/径向布局 + 星点云），已构成母题锁定。新概念必须尝试**全新空间母题**（实心 3D 体 / 流场 / 结构桁架 / 多面体 / 地貌 / 织体 等），且与已通过方向形态显著不同。先确认母题再动手（约束⑨），但母题本身必须新颖（见 §2.4）。
30. **【强制 3D 交互探索】新概念须同时提供「真三维交互」与「二维浮层交互」**：① 真三维 = 透视投影实现可 360° 轨道拖拽旋转（两轴 trackball，拖哪跟哪）+ 滚轮缩放的 3D 场景，而非仅平面平移缩放；② 二维协同 = 配套 2D 浮层（悬停探针 / 点击剖面 / 顶栏 KPI / 局部展开）让数据可读。Canvas2D 可用手动透视投影伪造 3D（杜绝 WebGL 黑屏风险），必要时 WebGL 仅作受控背景（try/catch + 编译/链接校验 + 降级兜底）。
31. **【交互必须舒服 · 步距连续无长跳】下潜/卷动/任何「空间位移」类交互，必须是平滑缓动（ease/lerp），使相邻内容**连续衔接**；禁止离散大跳距（如长卷段间留巨大空白）。判定标准：用户滚动/拖拽后，视野应顺滑移动，不出现「内容突然跳一大段」的断裂感。此条由识卷(21)「段距太长不舒服」反馈催生。
32. **【允许游戏化探索 · 禁廉价小游戏感】在「下潜/转向/锁定/追踪依赖链」等探索式交互上可投入更多资源、做出游戏化的**空间探索乐趣**；但**禁止抽测计分、输赢、排行榜**等「廉价小游戏感」（活字印知死因）。探索的目的在于让用户在 3D 结构里「走通知识脉络」，而非被游戏机制绑架。
33. **【亮色背景】用户明确要求「我需要亮色背景」**→ 新概念默认**暖白纸感亮底 + 深色墨线/墨色元素主导**（「墨落于纸」），不再用暗底霓虹。配色随之翻转：暗底的「明度=掌握度(暗→亮)」改为亮纸上的「墨色浓度=掌握度(掌握=浓墨深、薄弱=淡墨/青绿描边)」；零辉光/零 bloom 不变。GPU shader 受控背景亦须亮色（暖白纸 + 极淡墨晕/蓝图细网格），编译/链接失败即隐藏、CSS 纸纹兜底，**绝不黑屏**。与铁律㉛㉜同属"舒服 + 探索"谱系，但把底色从暗翻到亮。

34. **【禁止重复「轨道观察结构」交互范式】** 即便换了新母题（浮岛/下潜/平衡/桁架/晶格…），只要交互仍是「拖拽轨道旋转 + 滚轮缩放 + 点击飞入聚焦」这一套**观察式**范式，仍属重复——用户 2026-08-18 判"和之前几乎没区别"。新概念必须**同时更换交互范式**：用「织/编/折叠/显影/生长/书写」等**制作·生成·转化类**动效取代「观察一座 3D 结构」。可保留 3D 体量感，但**用户不旋转它、而是对它施加真实操作**（织线/摇机/温习/展开）——即本律对铁律㉚（强制 3D 轨道）的**定向修正**：㉚ 的"真三维"精神改由「固定取景的 3D 体 + 用户施操作 + 2D 浮层读数」诠释，**去掉"360° 轨道环视"强制要求**。3D 词汇 + 2D 浮层协同仍保留，呈现从"环视"转"施作"。

35. **【拒绝花瓶 · 必须有买点/价值闭环】** 用户 2026-08-18 核心批评：概念"看起来像无用的花瓶"，**欠缺"怎么在软件中利用上"与"买点"**。新概念必须回答两件事：① **落在软件哪里**——接哪个真实模块/功能（练考题库/复盘系统/错题集/每日复习）；② **买点/钩子是什么**——为何用户持续交互（抽取惊喜/收集/仪式感/进度可视化/自适应复习），且**每次交互直接产生学习价值**（获取知识/复习/推进掌握度/入册入集）。可借鉴「抽卡」范式：通过卡片/笺片获取知识 + 富有娱乐性。禁止"动效美但与学习功能脱节"的纯展示型概念。每条新概念交付时须在介绍里**显式写明买点与软件落点**。

## 5. 标准工作流（原型优先）

1. **对齐方向**：回读 `01_` 护栏 + `creative-motion-design`/`origin.md` 成功案例⑧⑩；先与用户确认母题再动手（约束⑨：同母题连否 2 次就换）。**本轮新增：新母题必须跳出「点-线-环-星」语法（约束29），并同时提供真三维轨道交互 + 二维浮层交互（约束30）。**
2. **Mock 真实界面**：镜像目标屏 chrome（顶栏 tabs：知识库/练考/复盘/<概念名> + 头像），让落点一目了然。
3. **真实操作驱动映射**：每个动效绑定具体用户动作（滚动/悬停/打开/聚焦/切换/点击/拖拽/缩放），受控非自跑。
4. **确定性物理**：弹簧+阻尼收敛；生成式元素仅在交互时出现、离开即收。避免失控混沌与 idle 空浮。
5. **造可玩原型**（先于文档）：单文件 HTML；Canvas2D 主舞台 + 受控 WebGL 背景（try/catch + 编译/链接校验，失败即隐藏、CSS 纸纹兜底）；**常开自动演示**（可关）保证受限预览里也有动效。
6. **校验**（见 §7）。
7. **先记日志再改代码**，并滚动总结用户反馈（§9）。
8. **交付 + 求方向**：展示原型，问用户方向对不对，再谈生产集成。

## 7. 校验与诚实限制

- **语法校验**：抽取内联 `<script>` 跑 `node --check`；或零依赖 CDP（Node22 内置 WebSocket 连系统 Chrome）无头探针，断言 **零报错 + 交互数值对**（如点亮 +1、收卡计数 +1、弹簧收敛、zoom 有界无 NaN）。
- **可靠性闸门**：WebGL 必须 try/catch + 编译/链接校验，失败即降级，杜绝黑屏；禁止把数组当标量传入、`mix(paper, NaN, …)` 等会写黑屏的写法。
- ⚠️ **识渊(22)教训（2026-08-17）**：WebGL2 + 多 canvas 降级方案在真实浏览器**连续两次全黑**，而 headless DOM 桩（用 Proxy 跳过真实 GLSL 编译、且未复现 canvas 上下文冲突）误报「全过」。**结论：涉及 WebGL2 / 多 canvas 的方案无法被 headless 可靠验证，不要再走这条路。** 后续新概念（自概念 23 识墟起）一律改走**单 canvas 纯 Canvas2D**（手动透视投影伪造 3D），彻底消除上下文冲突与 GLSL 编译黑盒，确保真机必显示；校验只需 `node --check` + 纯 Canvas2D 的 DOM 桩执行（无 GLSL 黑盒，逻辑层可真跑）。
- **概念 25 例外口径（亮色背景 + GPU shader 受控背景）**：用户 2026-08-18 明确要「亮色背景」并调用 GPU shader toolkit。据此采用 **「Canvas2D 自洽主舞台 + WebGL2 受控背景层」** 架构（即 §4 所允「WebGL 仅作受控背景」）：WebGL2 只画暖白纸 + 极淡墨晕/蓝图细网格，**任何编译/链接失败即 `display:none`**，主舞台 Canvas2D 透明底、自己不依赖 WebGL（亮纸由 CSS 兜底），故**即使着色器整段失败也只是少了背景纹理，绝不黑屏**——根除了识渊「降级取 2d 上下文得 null 崩溃」的死因。headless 仍以双模式探针验证（WebGL 可用 / WebGL=null 两种均须 onScreen>0、nan=false）。
- **诚实限制（必写进每个原型/日志）**：headless 只能证「能渲染 / 零报错 / 交互数值对」，**判不了审美**——任何视觉/手感改动必须由用户在真实浏览器（Chrome/Edge 直接开本地文件最稳）确认。
