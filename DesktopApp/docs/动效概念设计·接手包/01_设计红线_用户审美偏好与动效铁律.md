## 一、用户历次明确反馈（按概念时间线）

- **概念 0 砚心（过关）**：用户确认「这个方向是对的」。认可点 = 水墨+克制线动力学、真实操作驱动（滚动/悬停/切标签）、落真实界面（知识库 tabs+顶栏）、无游戏机制。→ 这是被验证的审美基因，新概念可借鉴其「克制+真实操作+落界面」精神，但**不可复制其形态**（创新第一）。
- **失败① 墨生（被动渐变+卡片）**：「无交互、无动力学，是网络上泛滥的 AI 套路味」→ 退回。
- **失败② 墨流体（自由流体）**：有动力学但「失控自跑、速度不可控（火球乱窜）、脱离真实界面」；且 `splat()` 参数错位写出 NaN→黑屏。→ 退回。
- **失败③ 活字印知（抽测压印）**：有交互但带「抽测/答对/计分」→「廉价小游戏感」。→ 退回。
- **概念 2 叠笺（过关方向，多版打磨）**：认可堆叠卡片方向，但要求「翻面/分级/特效/不穿模/直接操控/省手键盘/多卡包/错题栏」。最终沉淀：图表本体+风格层分离、形态优先于特效、特效门控最前卡、返回不重复入栈、背后卡静态。
- **概念 3 拓痕（废弃）**：「很烂，毫无美感，也没什么创新的动效，就像石头上放了几个按钮」→ 根因=静态底+按钮控件套路、shader 只算一块浮雕。
- **概念 4 织（废弃）**：「不懂织的设计意义是什么，废弃吧」→ 根因=织锦隐喻无清晰实用价值。
- **概念 5 复盘·生长（废弃方向）**：「不美观，图像古老了，需要新颖、创新但艺术现代化」→ 弃用有机/自然生长（年轮/树），转生成式流场+暗底霓虹。
- **概念 6 流光（废弃）**：「辉光等元素太过夸张」→ 整体放弃。教训：**零 bloom、克制零辉光**。
- **概念 7 素履 V1（冻结保留）**：「这个创意不错」；但「少了一些更突出的动效」→ 要更突出。v2–v5 森林/树/圆辉光连否：「不如第一版十分之一」「不要树了」「圆球特效很烂、烂大街」。教训：同一母题连否 2 次就换、勿在错母题上打补丁；圆球辉光 cliché；litPixels≠审美；抛弃已验证审美基因危险。
- **概念 8 弦（本轮否决）**：「很有意思，但在**信息可视化上还是很欠缺，无法直观地获得信息，只是作为艺术很有意思，但实用性大大降低了**」→ **新硬约束诞生：信息可视化优先、实用性优先**。
- **概念 9 层积（本轮否决·负面对照教材）**：「这次的设计，不好的地方在，图形太丑，**全部都是方块堆叠，颜色搭配也很烂，这版完全可以作为反面教程了**」+「**不要盯着时间轴做设计了，往其他方面发展**」。→ 三重否决：① 视觉形态丑（方块堆叠）；② 配色烂（硬色块撞色）；③ 母题错（又做了时间轴）。**新硬约束：告别方块堆叠、配色必须讲究（克制和谐、告别硬撞色）；放弃时间轴/时序母题，转向空间关系/结构/平衡/网络等非时序方向**。
- **概念 10 考点星图（本轮通过·方向认可）**：用户明确「**这次的创意出发点就不错，虽然有一些需要改良的地方，但是创意和视觉方面都可以**」→ 自概念 7 素履 V1 后第二个**被认可**的方向。通过要素：① 非时序（知识拓扑网，告别时间轴）；② 单主色墨青 + 明度层次编码掌握度（告别撞色）；③ 细线/点阵/拓扑网（告别方块堆叠）；④ 信息直观可读（节点大小=分值、明暗=掌握度、线粗=关联强度、顶部 KPI + 悬停精确面板）；⑤ 真实操作驱动（悬停高亮关联边 / 点击掌握由暗转亮+相邻受控弹簧脉冲 / 拖拽平移缩放）。**本配方定为后续概念新基线**（见约束⑭）。改良点（用户未展开，待下版打磨）：方向定了，细节后续优化。
- **概念 11 气脉流转（本轮否决·非常失败）**：「不好看，点密度不够，导致所谓的气脉很大很不好看，又约束在一个长方形内，周围是截断的，排版上也不好看，这次非常失败」。双重死因：① **点/采样密度太低**——仅约 20 个采样点插值出整片连续标量场，"又大又空、很难看"；② **被硬框在长方形里、四周截断**，排版丑。→ **新硬约束：信息载体必须有足够密度（拒绝稀疏采样插值出大而空的场，改用密集离散元素）；形态边界须自然（圆形/放射/有机/全幅深底漂浮），勿用硬长方形把内容截断**（见约束⑮⑯）。
- **概念 12 识海·星砂（本轮通过·高度认可 + 用户追加升级）**：用户明确「**这一版真的很有意思，完完全全的创新，你做到了**」→ 自概念 10 后评价最高的通过方向（"完全创新"高于"创意出发点不错"）。认可原因（用户原话三点）：① 能**直观看到未掌握的点并与之交互**；② 既充满**星空的美**、又**丰富了信息可视化**；③ **星团间有连线**，想解决同类型题可**沿连线溯源**。→ 在概念 10 新基线之上进一步创新。用户随后追加升级设想（**已实现**）：① **三通道颜色编码**（色相=学科来源 / 纯度=难度，高=难 / 明暗=掌握度，高=亮）——"颜色带来的信息可视化将会提升几个档次"；② 点击星点弹出**塔罗星卡**（正面类型/来源/难度/掌握度+操作，背面翻面看真题）；③ 星卡可**拖入「图谱」收藏**（重命名自错题集，贴合星空主题）；④ 与**叠笺**卡片系统结合。→ 升级版原型已构建并通过校验（见约束⑰ 数据着色豁免）。

- **概念 12 v3（本轮就地迭代·卡片/图谱重写）**：用户认可方向与三通道配色（"颜色的实现很好"），但判**卡片与图谱太 low**，要求就地改（不换母题）：① 卡片**从点击处飞出、旋转、落屏幕中央**的**塔罗封面**（竖版比例、无大字无按钮、像收集品），样式照搬**叠笺**；② 难度用**专属色光晕/发光颜色**表达（抽卡稀有度：易青/中蓝/难紫/极金，越难越亮），并搬入叠笺**层级显示**；③ 右侧**图谱**的显隐与排布**照搬叠笺**（scrim 变暗 + 右栏滑入 + 拖入收集 + 收藏家横排叠卡）；④ **去按钮**，改用**拖拽 / 键盘 / 悬停**完成交互（要创意更要美观艺术）。→ 见约束⑱(抽卡稀有度光晕)⑲(去按钮交互动效)⑳(封面即封面)。
- **概念 12 v4（卡片/图谱细化·用户 5 条精准修改）**：方向不变，按反馈就地改：① **切角必须有描边**（clip-path 切角用内联 SVG polygon 描边，non-scaling-stroke 保证均匀，色=稀有度）；② **封面不要矢量图形/雷达**，只叠一层**棱镜折射 + 质感**层（后期用户自己换封面）；③ 卡片入场**不要绕中心旋转，要翻转**（rotateY 翻转 + 缓慢 .9s + 之后太空漂浮 translateY/rotateZ）；④ **背面内容必须保留、能翻面**（F/空格翻面看真题）；⑤ 右侧**图谱常驻不自动收起**（点内部卡片不塌），且卡片**不要未来风**，要正常卡片 + 轻微边角变化。→ 新增约束㉑(切角描边/正常卡片)㉒(翻转非旋转/漂浮慢)㉓(封面=棱镜层,去矢量)㉔(图谱常驻pinned)。
- **概念 12 v5（卡片从零重做·用户：翻面/卡片设计仍不行，整卡重写非修补）**：v4 仍是补丁式，翻面轴错乱/背面闪现未根治。v5 **整卡重写**：把「入场飞行 / 太空漂浮 / 视差偏转 / 翻面」四种变换**彻底拆到四个独立 DOM 层**（`#card`→`.float`→`.stage`(perspective)→`.tilt`(偏转)→`.flip`(翻面)→`.face×2`），各管一种变换、互不干扰；翻面幅度控在 ±90° 内（绝不露背面）；悬停视差偏转独立在 `.tilt` 层；背面题面重做清晰排版；图谱 mini 卡去未来风改正常圆角卡。→ 新增约束㉕(多变换必须拆到独立 DOM 层)。星海/三通道配色/探针/KPI/图谱常驻逻辑全保留。校验：零报错、翻面正常、点亮+1、图谱常驻。
- **概念 12 v6（回退至 v2·用户：v5 又搞砸了）**：v5 交付后用户判「不行不行，你又搞砸了」，要求「回退到第二版的星图」。v3/v4/v5 持续在卡片上堆新风格层（塔罗封面→棱镜→四层独立变换），均未被认可。决策：**整体回退到 v2**（正常考点卡+三按钮+rotateY翻面+弹簧弹入+拖入/按钮收图谱，非强制常驻）。已移除塔罗封面/抽卡光晕/棱镜/八边切角/漂浮/四层；星海/三通道/KPI/探针/点亮/缩放平移保留。校验零报错、翻面/点亮+1/收卡计数+1 全部生效。→ **新增约束㉖（已认可版本勿在其上堆新风格层；连续否定时优先回退到上一认可版而非继续打补丁）**。

## 二、提炼的用户铁律（最新版，覆盖全部反馈）

1. **创新第一、非大众化**：拒绝 SaaS 蓝白渐变+圆角卡片那套，要有辨识度与创意。
2. **有意义 + 实用价值优先**：不能为动效而动效。织（无意义）、拓痕（背景+控件套路）被否的根因就是缺实用价值。动效须服务于「让颜色/图形/功能更直观」。
3. **现代感、艺术现代化**：弃用「古老」的有机自然形态（年轮/树/生长）；向往 Linear/Vercel 式克制工程数据美学。
4. **克制、零辉光、零 bloom**：流光因夸张辉光被否；圆球光晕 cliché（概念 7 教训）。用色深/笔触/描边表达，不用加性光球。
5. **【最高优先级·本轮新增】信息可视化优先、实用性优先**：动效必须让数据**直观可读**，不能只是好看。具体要求——
   - 图表本体（坐标轴 + 数值刻度 + 标签 + 可读几何载体）先于风格层；
   - 交互要能**直接获取信息**（如拖动框选区间 → 实时聚合读数：均值/总数/连续天数）；
   - 拒绝「艺术有趣但读不出数据」的纯氛围表达（弦之鉴）。
6. **真实操作驱动、确定可控、非游戏**：拒问答/计分/抽测/输赢；动力学须阻尼收敛，不失控乱跑、不 idle 空浮。
7. **落真实界面**：看得见加在哪（mock 真实 chrome/tabs）。
8. **图表本体 + 风格层分离**（约束⑨）；**形态优先于特效**（⑩）；**禁用软圆辉光作主特效**（⑪）。
9. **先确认母题再动手**：概念 7 森林连否教训——同一母题连否 2 次就换路子，勿在错母题上打补丁；动手前先与用户对齐方向。
10. **【本轮新增】每次都要总结用户反馈与想法**：让创意不偏离。本文件即该总结的持久载体。
11. **【本轮新增】形态美感优先、告别方块堆叠**：用户明确「图形太丑、全部都是方块堆叠、可作为反面教程」→ 拒绝柱状/色块/方块堆叠式载体；改用有机曲线、细线、点阵、连续面、拓扑网等更精细优雅的几何语言（仍须零辉光）。
12. **【本轮新增】配色必须讲究（和谐、克制、有层次）**：用户明确「颜色搭配很烂」→ 拒绝多硬色块同屏撞色（amber/slate/terracotta/teal 一锅炖）；采用「单主色 + 灰度层次」或「协调类比色」，克制而有质感；信息维度靠明度/饱和度/大小/位置区分，不靠撞色。
13. **【本轮新增】放弃时间轴 / 时序母题**：用户明确「不要盯着时间轴做设计，往其他方面发展」→ 弦(时序弦波)、层积(时序岩芯)连续两次失败在时序；新概念必须**非时序**，转向空间关系网 / 结构平衡 / 力量场 / 知识拓扑 / 形态映射 等方向。
14. **【本轮新增·通过的配方即新基线】概念 10「考点星图」获认可（创意出发点 + 视觉均可）**，其配方作为后续概念**新基线**：非时序 + 单主色（墨青）+ 明度层次编码掌握度（暗→亮）+ 细线拓扑网（线粗 = 关联强度）+ 力导向确定性布局 + 顶部 KPI（总数/掌握率/平均掌握度/薄弱数）+ 悬停精确面板 + 真实操作驱动（悬停高亮 / 点击掌握弹簧脉冲 / 拖拽）。**之前不好的（概念 8 弦、概念 9 层积、概念 11 气脉流转）正式摒弃，不再作为方向参考**；仅保留概念 9 为「负面对照教材」以警示方块堆叠 / 撞色 / 时序三宗罪。用户原话：「之前不好的就摒弃掉……我相信慢慢地你也就知道该怎么做了」。

---

15. **【本轮新增】信息载体必须有足够密度，拒绝稀疏采样插值出「大而空」的场**：气脉被否因「点密度不够 → 气脉很大很不好看」。数据载体不能用极少采样点插值出整片连续面（稀疏→大而空→丑）；要么用**高密度离散元素**（密集点阵 / 细密线网 / 密集小单元 / 大量节点），要么干脆不用连续场形式。与约束⑪（形态美感优先、告别方块）叠加。
16. **【本轮新增】形态边界须自然，拒绝硬长方形截断**：气脉被否因「约束在长方形内、周围截断、排版丑」。可视化主体不应被一个硬边矩形框死、四周被切。优先用**圆形 / 放射 / 有机 / 全幅深底漂浮**等自然边界；若必须用矩形画布，须让内容在框内留白呼吸、不贴边截断。

17. **【本轮新增·数据着色豁免】用颜色系统性编码信息是可接受的（经用户明确提议并认可）**：用户要求"不同难度/不同类型用不同颜色——色相=来源/类型、纯度=难度（高=难）、明暗=掌握度（高=亮）"。这是对铁律⑫（配色克制和谐、告别硬撞色）的**定向豁免**——当且仅当颜色用于**系统性编码数据维度**（而非装饰性撞色）时允许多色相。仍须守：① 每学科/类型 = 一个**协调色相族**（非彩虹乱炖）；② 饱和度由难度调制（低饱和=易、高饱和=难）；③ 明度由掌握度调制（高=亮、低=暗）；④ 整体克制、不刺眼、**零辉光**。该做法与"信息可视化优先"（约束⑤）一致，是概念 12 通过的关键加分项。

18. **【本轮新增·卡片即收藏品·抽卡稀有度】概念 12 用户明确「卡片要像收集品、用专属色光晕/发光颜色体现难度等级，就和抽卡游戏一样」**→ 卡片（尤其点开的详情卡）应被当**一件收藏品/抽卡卡牌**来设计：难度等级 = 稀有度（易/中/难/极），用**专属色光晕 + 发光颜色**表达（如 易=青·中=蓝·难=紫·极=金，越难越亮），而非用文字标难度；卡面用**切角框（带描边）+ 稀有度专属色光晕**等"卡牌/阵营"视觉语汇（借终末地/方舟，非游戏化机制）；**避免四角准星 / 扫描线等"未来 HUD"装饰**——用户明确嫌其"未来风、丑"，要的是**正常卡牌 + 轻微边角变化**。这把"难度"从数字变成**一眼可感的视觉稀有度**，是信息可视化的高级形态。

19. **【本轮新增·去按钮、交互动效优先】用户明确「那些按钮都通过交互来完成，比如拖拽比如键盘控制，按钮实在是不好看，我需要的是创意，但在此基础上更多的是美观，是艺术」**→ 凡是能用**拖拽 / 键盘 / 悬停 / 手势**完成的交互，就不要用可见按钮（尤其是矩形文字按钮）。例如：拖卡片入收藏区 = 收藏；`Esc` 关、`L`/双击 = 点亮；悬停边缘 tab = 展开面板。交互即动效，动效即交互——把"可操作性"藏进物理直觉里，画面更纯粹、更艺术。

20. **【本轮新增·封面即封面】点开的详情卡应是「封面」而非「表单」**：无大字标题、无按钮、无表单式排版；只呈现几何族徽 / 抽象纹样 / 稀有度光晕 / 极小号标签。信息密度让位给**美感与收藏感**，具体数据（题面/数值）留给悬停探针或次级浮层。这与"艺术 > 实用呈现"的本次诉求一致（实用数据已由星海 / KPI / 探针承担）。

21. **【本轮新增·切角必须有描边 / 正常卡片】用 `clip-path` 做切角时**，`border` 会被裁掉导致"切角没有描边"——必须用**内联 SVG `<polygon>` 描边**（同形状，色=主题/稀有度，配 `vector-effect:non-scaling-stroke` 保证粗细均匀）补出边线；或在切角处加发光描边。卡片整体走**正常卡牌**路线（圆角/微切角 + 细描边 + 柔和光晕），**拒绝"未来 HUD"式夸张装饰**（四角准星、扫描线、雷达族徽等），用户判定其"很丑"。

22. **【本轮新增·翻转而非旋转 / 漂浮慢】卡片入场用绕 Y 轴 `rotateY` 的"翻转"**（`-168°→0°`，缓慢 ~.9s）从点击点飞向中央，**不是绕中心 spin**（用户明确"不要旋转，要翻转"）。落定后叠加轻微 **太空漂浮**（无限 `translateY±7px + rotateZ±1.1°`），速度要慢、要"轻"，呈现漂浮感而非动效炫技。

23. **【本轮新增·封面=棱镜层，去矢量】详情卡封面不要画矢量图形 / 雷达 / 族徽**——用户说"不好看、后期自己加封面"。正确做法：封面只叠一层 **棱镜折射效果**（玻璃质彩虹/虹彩渐变，`mix-blend:screen` 或柔和叠加）+ **极淡质感纹理**（斜纹/噪点，无外链资源），让用户后期直接替换封面层即可。保留稀有度光晕作为"边缘光效"。

24. **【本轮新增·收藏面板常驻】右侧图谱/收藏面板应"常驻可点"**：用户点了面板里的卡片，面板**不能自动收起**（原 `mouseleave` 自动隐藏导致"点里面卡片就塌"）。改为 **pinned 模式**——拖卡/点边缘 tab 即钉住打开，再点 tab 才关闭；内部卡片可反复点选。面板内卡片用**正常小卡缩略图**（带稀有度色条），而非细条。

25. **【本轮新增·多变换必须拆到独立 DOM 层，互不干扰】概念 12 v5 教训**：当一个元素同时需要「入场飞行 / 漂浮 / 视差偏转 / 翻面」等多种变换时，**绝不能把它们堆在同一层或少数几层 `preserve-3d` 嵌套里、再用 2D `rotate` 往父层叠**——多层 `rotateY`/`rotate` 会互相耦合，导致翻面轴错乱、拖拽抖动、背面闪现。正确做法：把每种变换**拆到各自独立的 DOM 层**，各管一种变换：最外层只管入场 `translate+scale`；内层之一只管漂浮 `translateY+rotateZ`；`perspective` 容器下，子层之一只管视差偏转 `rotateX/Y`，另一子层只管翻面 `rotateY(0/180)`；`.face` 两面各 `backface-visibility:hidden`。四层分离后翻面/偏转/入场/漂浮**不再互相打架**。该约束适用于一切"卡片飞出+3D 翻转+悬浮"类动效。

29. **【本轮新增·突破母题锁定】禁止在「点-线-环-星」2D 词汇内打转**（详见 canonical 文档 `DesktopApp/docs/用户审美偏好与动效铁律.md` ㉙㉚）：新概念必须尝试全新空间母题（实心 3D 体 / 流场 / 结构桁架 / 多面体 / 地貌 / 织体 等），与已通过方向形态显著不同；并须同时提供真三维轨道交互 + 二维浮层交互。
30. **【本轮新增·强制 3D 交互探索】** 真三维（透视投影 + 360° 拖拽旋转 + 缩放）+ 二维浮层（悬停探针 / 点击剖面 / KPI）协同。Canvas2D 可手动透视投影伪造 3D 杜绝黑屏。
31. **【本轮新增·亮色背景】用户明确要求「我需要亮色背景」**→ 新概念默认采用**亮色（暖白纸感）背景**，深色墨线 / 墨色元素主导（「墨落于纸」），而非暗底霓虹。配色随之翻转：暗底上「明度 = 掌握度（暗→亮）」改为亮纸上「墨色浓度 = 掌握度（掌握 = 浓墨深、薄弱 = 淡墨 / 青绿描边）」；零辉光 / 零 bloom 不变；背景可辅以极淡墨晕或蓝图细网格（GPU shader 受控背景亦须亮色、失败即 CSS 纸纹兜底，绝不黑屏）。

34. **【本轮新增·禁止重复「轨道观察结构」交互范式】** 即便换了新母题（浮岛/下潜/平衡/桁架/晶格…），只要交互仍是「拖拽轨道旋转 + 滚轮缩放 + 点击飞入聚焦」这一套**观察式**范式，仍属重复——用户 2026-08-18 判其"和之前几乎没区别"。**新概念必须同时更换交互范式**：用「织/编/折叠/显影/生长/书写」等**制作·生成·转化类**动效取代「观察一座 3D 结构」。可保留 3D 体量感，但**用户不旋转它，而是对它施加真实操作**（织线/摇机/温习/展开）——即本律对铁律㉚（强制 3D 轨道）的定向修正：㉚ 的"真三维"精神改由「固定取景的 3D 体 + 用户对其施加操作 + 2D 浮层读数」诠释，去掉"360° 轨道环视"强制要求。详见权威文件 `DesktopApp/docs/用户审美偏好与动效铁律.md` 铁律㉞。

- **【铁律㉟ · 拒绝花瓶 · 必须有买点/价值闭环】**（2026-08-18 用户核心批评："欠缺的主要是怎么在软件中利用上……怎么成为买点还是有欠缺，看起来像无用的花瓶"，并点名「抽卡」项目为正面范式——"用户可以通过卡片获取知识，且富有娱乐性"）：每个概念必须回答两件事：① 落在软件哪里（接哪个真实模块/功能，如练考题库/复盘/错题集）；② 买点/钩子是什么（抽取惊喜/收集/仪式感/进度可视化/自适应复习），且每次交互都直接产生学习价值。可借鉴「抽卡」范式：通过卡片/笺片获取知识 + 富有娱乐性，而非纯观赏。禁止"动效很美但与学习功能脱节"的展示型概念。
