## 2026-08-05（夜·续·拾叁）· 专栏可编辑化（每账户私有 + 桌面端 CRUD）

### 背景
用户反馈：网页端专栏可在云端自定义，但桌面端「我的账户」下无编辑入口，内容为静态种子不可修改。
需求：每个账户（含演示账户 demo）拥有自己的专栏集合，支持新建/编辑/删除，数据按账户隔离存储。

### 改动清单

**数据层**
- `Data.h`：新增 `struct Column { id, title, body, author, createdAt, updatedAt }`；声明 `RoadmapSeedBody()` 将 `BuildDefaultContent().roadmap` 格式化为可读正文。
- `Data.cpp`：实现 `RoadmapSeedBody()`（三原则 / A段战线 / 决策路径 / 月历）；`ApplyCurrentAccount()` 新增 `ReloadColumns()` 调用（账户切换时刷新专栏缓存）。

**存储层** (`Store.h` / `Store.cpp`)
- 新增 `ColumnsFilePath()` / `LoadColumns()` / `SaveColumns()` / `ReloadColumns()` / `Columns()` (const getter)。
- `LoadColumns()`：懒加载 + 缓存（`m_colsLoaded`/`m_colsRoot`）；演示账户首次加载时自动播种「我的总线路图」并落盘 `columns.json`。
- `SaveColumns()`：JSON 序列化 → 写入 `accounts/<name>/columns.json` → 标记 Cloud dirty。
- `BuildPayload()` / `ApplyPayload()`：新增 `"columns"` 块，纳入导出/导入/云同步。
- `Reload()`：调用 `ReloadColumns()` 清除缓存。

**视图层** (`RoadmapView.h` 完全重写 / `RoadmapView.cpp` 全新)
- **布局**：Section 头 "专栏" + 面包屑 "每个账户私有可编辑"；右上角 "+ 新建专栏" 按钮；
  - **私有专栏区**：每张卡片 = 标题(粗) + 元信息(作者·日期) + 正文预览(3行截断,省略号)；悬停显示 编辑/删除 徽标；
  - **空状态**："还没有专栏，点击右上角新建。";

- **交互**：
  - 点击卡片 → 打开 Win32 EDIT 编辑器模态框（标题单行 + 正文多行），支持中文 IME（DPI 缩放、ESCAPE 取消、ENTER 保存）；

  - 删除徽标 → 即删即存（无需确认，Undo 靠云同步历史）；
  - 返回首页按钮。
- **动画**：卡片入场 stagger（每张延迟 0.06s）、编辑器淡入/滑出。

## 2026-08-04（夜·续·拾贰）· 云端对接 §3–§5 客户端落地（实时自习室 / 公共专栏 / 媒体库）+ 契约测试全绿

- **§3 实时自习室（WebSocket）传输层重大反转**：初版设计用 WinHTTP `WebSocket` API，实装时发现本环境 `WinHttpWebSocketCompleteUpgrade` **恒定返回 `ERROR_WINHTTP_INVALID_SERVER_RESPONSE(12152)`** —— 即便服务端回包完全合规（已用裸 TCP 复核 101 状态行 + `Sec-WebSocket-Accept` 正确）、连微软官方示例的逐字复刻（`tools/ws_min.cpp`）对本地与 mock 均失败。**结论：本机 WinHTTP WS 实现不可用，裸 socket 正常。** 遂把 `src/net/Realtime.h` + `Realtime.cpp` 重写为**手写 RFC 6455 over Winsock（`ws2_32`）+ CNG（`bcrypt` 做 SHA1/随机数）**，仍为系统库、零第三方依赖；行为可控，与服务端 `Server/src/realtime/ws.js` 口径一致。
- **Realtime 重写要点**：`SOCKET` 存 `std::uintptr_t m_sock`（`INVALID_SOCKET`）；新增 `SendOp(opcode,payload)`（取锁发帧）/ `CloseSock()`（唤醒阻塞 `recv`）/ `m_wake`（Reconnect 跳过退避）；`ConnectAndRun()` 返回 bool（曾握手成功即重置退避）；上行帧**强制掩码**（RFC 6455 §5.3）；握手校验 `Sec-WebSocket-Accept = base64(sha1(key+GUID))`；支持分片续帧（OP_CONT）、ping/pong 自动应答、close。
- **§4 公共专栏 + §5 媒体（REST，复用 `Cloud::Call`）**（`Cloud.cpp #9`）：新增 `GetColumns / LikeColumn / CommentColumn / GetMediaList / UploadMedia / DeleteMedia`（均后台线程走私有 `Call`，自动带 Bearer + 401 刷新）与 `RunAsync(job)` / `AccessToken()`。
- **`Http.h`（#7）**：`Request` 增加 `contentType` + `extraHeaders` 参数；`POST /media/upload` 走 `application/octet-stream` + `X-Meta: base64(JSON)` 头；二进制体用 `std::string` 承载（含 `\0` 安全）。
- **`App.cpp`（#10）接线**：`Cloud::Init()` 后调 `Realtime::Instance().Init(epProvider, tokenProvider, refreshProvider)`；退出路径 `Shutdown()`；`Cloud::BindAccount` 内追加 `Realtime::Instance().Reconnect()`（Realtime.h 不回 include Cloud.h，无环依赖）。
- **`CMakeLists.txt`**：`target_link_libraries` 在 `winhttp` 后追加 `ws2_32 bcrypt`。
- **契约测试（`tools/ws_contract_test.cpp`，由 `.ws_verify.cpp` 提升为正式回归工具）**：用真实客户端网络层（`Http.cpp + Realtime.cpp`）连运行中的 `Server`，逐项验证 —— 7 条下行（`auth:ok / rooms:list / room:joined / presence / chat:msg / music:list / col:changed`）+ `GET /media/list`（200）+ `POST /columns`→广播 `col:changed`。结果**全绿（EXIT=0）**。
- **主程序**：`source tools/msvcenv.sh && cmake --build build --target Flori` 重建成功，零告警。
- **设计文档同步更正**：`docs/云端对接设计·客户端§3-§5.md` 中所有「WinHTTP WS」描述已更正为「手写 RFC6455 / Winsock」，并在 §2 追加「传输层更正」说明；并行客户端团队据此落地 `RoomView/RoadmapView/MediaView` 的接入（接入点见该文档 §4）。
- **闭环状态**：§3 实时 + §4 专栏推送 + §5 媒体，客户端对接层（传输 + REST + 接线）全部代码落地并通过真实端到端契约测试；剩余仅三视图 UI 接线（持有本地占位，待并行客户端团队实现）。

## 2026-08-04（夜·续·拾壹）· 四视图文字重叠根因修复（Canvas 裁剪 + 矩形重算）

  - 日记「共 N 条」与第 3 条复盘条目重叠：作息/复盘卡高度 176→**200px**，日记行步进 40→**42px**。
- **P0 — MaterialsView 导语卡正文截断 + 避坑溢出（4 项）**：

## 夜·续·拾柒（2026-08-05 17:35）

**EDIT 文字「疯狂频闪」专项根治**（`Window.cpp` 主窗口样式 + `App.cpp` 呈现循环）

- **用户复报**：上轮（拾陆 §1）把 `RedrawWindow` 改为「只重绘 EDIT 子窗口本身」后，文字可见了，但**文字在疯狂频闪**。说明「每帧强制重绘 EDIT」本身与 `Present()` 仍是打架的两方。
- **最终根因（精确）**：本工程 `DXGI_SWAP_EFFECT_SEQUENTIAL`（blit 模型）下，swap chain 与主窗口**共享同一块 GDI 表面**，EDIT 子窗口的像素也画在这块共享表面上。`Present()` 每帧把后台缓冲 bitblt 到整块客户区——`WS_CLIPCHILDREN` 缺位时它会**覆盖** EDIT 所在区域 → 原始「不可见」；给 EDIT 每帧 `RedrawWindow` 强制刷新 → 刷新与 `Present` 在 DWM 合成期赛跑 → **频闪**。两症状同源。
- **根治修复（两步）**：
  1. `Window.cpp` 主窗口样式加 `WS_CLIPCHILDREN`（`WS_OVERLAPPEDWINDOW | WS_CLIPCHILDREN`）。blit 模型的 `Present` bitblt 经 `GetDC(parent)` 时会**裁剪掉子窗口区域**，从此 `Present` 永不再碰 EDIT 的像素。
  2. `App.cpp` 呈现循环**彻底移除**每帧 `RedrawWindow(EDIT)`。EDIT 仅在自身「创建 / 输入 / 焦点变化」时由系统自绘（事件驱动，非 60fps），其像素常驻共享表面、被 DWM 合成在最上层。
- **效果**：频闪根因（双呈现打架）消失；EDIT 像素不被 `Present` 覆盖 → 可见且稳定。比上轮方案更彻底，且不再依赖每帧重绘。
- **风险排除**：不会回退到「不可见」——`WS_CLIPCHILDREN` 正是让 blit 模型 `Present` 跳过 EDIT 区域的关键，EDIT 自有像素得以保留。

## 2026-09-11 · 统一输入框 v2（1×1 透明代理 + D3D 自绘，根除「白块」）
### 背景
用户实测反馈：所有「点击输入框→弹出多余白块、文字打在白块上」的位置都要修。原因存在于**所有**单行输入框（登录页 5 字段、好友页添加/私聊、设置、档案、管理、择岗、成就、自习室聊天/白名单等近十个视图）；多行「今日复盘」弹层、路线图编辑器也在此列（白块是 EDIT 默认白底自绘盖住设计好的纸面）。

### 根因
旧模式「全尺寸代理 EDIT + `WM_SETREDRAW(FALSE)` 禁自绘」在 GDI 子窗口层不可能靠禁绘彻底消除自绘——EDIT 一旦显示/聚焦/输入就会用其默认白底+系统字体画出内容，且主窗口 `WS_CLIPCHILDREN` 让 D3D 位块传送永远刷不到那块区域；D3D 层的自绘文字被 EDIT 的 GDI 表面物理覆盖。**之前所有截图自检都通过，恰恰因为 D3D backbuffer 不含 GDI 子窗口**——截图验证的是「不崩」而不是「无白块」。

### 方案
新建 `ui/FieldEdit.h/.cpp` 统一组件，**物理消除**病根：

- **1×1 `WS_EX_TRANSPARENT` EDIT 代理**：只承担键盘 + IME 焦点；对鼠标完全透明（点击直达主窗口，D3D 命中测试照常）；永远不覆盖字段；
- **文字 / 光标 / 选区 / IME 组合串全部 D3D 自绘**（复用既有 `FieldText` 系列：`PaintFieldEdit` / `PaintFieldEditIme` + `ImeReadComposition` + `ImeSetCandidatePos`）；
- **`HandleMouse`**：视图把鼠标事件转交，由本组件通过 `CharIndexAtX`（DWrite 测量）做点击定位 + 拖拽框选（锚点夹取到字段边界以支持拖出框继续延伸）；
- **1×1 代理随光标 / 组合串位置移动**：`PlaceProxy` 每帧检查像素是否变化，避免每帧 `SetWindowPos`；IME 候选窗通过 `ImmSetCandidatePos(h, 0, boxH, dpi)` 锚定到代理点。
- **共享 `Proc` 静态 WndProc**：`UserData` 指向 `FieldEdit*`，`onEnter` / `onEsc` / `onKillFocus` 三个 `std::function` 回调（IME 组合中不吞回车/Esc——归输入法）；`WM_KILLFOCUS` 提交时 `m_active` 已置否的 `End()` 路径不再二次回调，防递归。

## 2026-09-11 · 登录/注册拆页 + 封面仪式回归

### 需求（用户）
1. 登录界面只放登录，注册新账户要「切出来」成为独立页，不再上下混排。
2. 封面页恢复「和原来一样」：开屏永远先有故事感封面，再进软件本体。

### 现状问题
- `LoaderView` 播完的跳转是「有会话→cover，无会话→直接 login」：无会话（首启/登出后）完全跳过封面。
- `CoverView` 进入按钮写死 `Go(L"home")`（无会话时会漏过登录门槛），且按钮/拉丁名还是旧项目残留文案「进 入 律 己」「L Ü J I」。
- `LoginView` 模式 B 把登录表单、分隔线、注册表单排在同一页。

### 方案
- **启动流**：loader 播完一律 `Go(L"cover")`；封面进入（按钮 / 回车 / 空格）走新增的 `GoEnter()`——`HasSession()→home`，否则 `→login`。登录/注册成功后 `EnterHome` 改为直接 `Go(L"home")`（封面仪式已由 loader→cover 保证，不再二进封面）。完整流：**loader → cover →（进入）→ login →（登录成功）→ home**。
- **LoginView 三页状态机**：`bool m_showForm` → `enum Page { PG_LIST, PG_LOGIN, PG_REG }`。登录页 = 标题 + 账户名/密码 + 登录按钮 + 「还没有账户？注册新账户 →」链接（+ 有账户时「← 返回已有账户列表」）；注册页 = 标题 + 三字段 + 注册按钮 + 「← 返回登录」。`Layout` 三条流各自推进，按 `m_page` 取 contentHeight；`DrawField`/`DrawButton` lambda 提到 Paint 的页分支之外共用。顺手清掉头文件里 v2 迁移遗留的死声明（`EnsureEditor` / `EditProc`）。
- **封面品牌修正**：按钮文案改为由 `Content::appName` 动态拼字距（「芙 洛 理」）；拉丁名改用 `C.appNameLatin`（Flori）并按实测宽度居中。

### 编译 & 验证

## 2026-09-11 · 登录页打磨：垂直居中 + TAB 跳转 + 密码眼睛 + 访客入口

### 需求（用户）
1. 登录 UI 太偏上 → 调到视口中间。
2. 输入框之间 TAB 跳转。
3. 密码框右侧加显示/隐藏的眼睛图标（可网上获取或自设计）。
4. 登录界面提供访客模式：不进云端、按本地运行。

### 实现
- **垂直居中**：`Layout` 改两遍流——`BuildFlows(bodyTop)` lambda 跑第一遍测量内容高度，放得下则第二遍以 `(availH - contentH)/2` 为起点重跑（内容超高则保持顶部起点交给滚动）。
- **TAB 跳转**：编辑态捕获 `in.keyDown[VK_TAB]`，按当前页字段序列（登录 2 个 / 注册 3 个）循环跳转；Shift+Tab 反向（`GetKeyState(VK_SHIFT)`）。跳转 = `CommitEdit()` + `BeginEdit(下一字段)`。
- **眼睛图标**（自绘，零外部素材，贴合纸面档案风）：`DrawEye` = 圆环（StrokeCircle 6.2）+ 瞳孔（FillCircle 2.1），明文显示中加斜杠提示「点击隐藏」；悬停变印章色。`FieldEdit` 新增 `SetPassword(bool)`——编辑中实时切换掩码映射（不动缓冲）；`BeginEdit` 按 `m_reveal[]` 状态决定初值掩码。命中区 `m_eyeRect[5]` 在 Layout 时随密码字段生成（右侧 28×46），点击眼睛的本帧跳过该字段 HandleMouse（防光标乱跳）与 BeginEdit 重入。
- **访客入口**：登录按钮下新增「访客模式 · 本地试用，不进云端」行（青玉色 hover，与列表页访客行同款）。云端隔离是既有架构：`AccountStore::Guest()` 调 `Cloud::BindAccount(空)`（访客不碰云端），`Cloud::Init` 对访客不绑定账户；本批只补登录页入口。

### 编译 & 验证

## 2026-09-11 · 三处修复：账户弹层重叠 / 专栏页左上角杂字 / 知识库页内拖入

### 需求（用户截图反馈）
1. 账户卡片弹层：菜单「设置」行与「退出登录」按钮重叠。
2. 专栏页左上角窗口边缘有一坨切碎的字。
3. 考点·知识库写着「可拖入」，实际拖文字/文件进去没有任何反馈，收集不了。

### 根因与修法
1. **弹层重叠**：`TopBar::Update` 里面板高度写死 `ph = 286`，5 个菜单项从 `py+110` 起每项 30px 排到 `py+260`，而退出按钮固定在 `py+236..py+272` → 「设置」行（230..260）被盖住 24px。改为按项数动态计算：`ph = 110 + n*30 + 10 + 36 + 14`（5 项 → 320），菜单与按钮之间留 10px 间隔。
2. **左上角杂字**：`RoadmapView::PaintEmpty` 用的 `m_emptyRect` **从未被赋值**（恒为 `{0,0,0,0}`）。空列表时 PaintEmpty 拿退化矩形画「空白」NumberTag（`r.right-64..r.right-14` = `-64..-14`）和两行文案（`r.left+22 .. r.right-22` = `22..-22` 左右颠倒），D2D 对负宽布局矩形的处理未定义 → 在窗口左上角渲染出被切碎的字形残迹（截图自检可复现：`--shot --route roadmap`）。修复：`RelayoutList` 给 `m_emptyRect` 赋合法矩形（x0, m_listY, +contentW, +190），并补 `flow.block(190+16)` 占位块——否则空态卡又和「返回首页」/「公共专栏」区重叠（修复过程中实际发生过，已一并验证）。
3. **知识库拖不进**：OLE 放目标只注册在右下角专注浮窗上，而浮窗默认隐藏（看板娘悬停才显示）→ 主窗口上拖入毫无反应。新增 `src/core/KnowledgeDrop.h/.cpp`：
   - 主窗口注册 `IDropTarget`（`RegisterDragDrop`，主线程已是 OLE STA）；
   - 接受 `CF_UNICODETEXT`（浏览器/PDF 选中文字）与 `CF_HDROP`；单个 `.md/.txt/.markdown`（≤64KB，UTF-8 优先退 ANSI）读正文建卡、标题取文件名，其余文件记路径；
   - 反馈三件套：悬停时 `KnowledgeDragActive()` → KnowledgeView 画印章红蒙层 + 内框 + 「松开鼠标，收录为考点」横幅；落点成功 `KnowledgeRev()` 版本号 +1 → KnowledgeView 轮询刷新列表 + Toast「已收集考点」+ 托盘气泡。
   - KnowledgeView 提示文案同步改为「直接拖进本页面即可收集」。
