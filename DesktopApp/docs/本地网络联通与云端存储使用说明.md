# 本地网络联通与云端存储使用说明

> 适用于芙洛理桌面端 + 服务端 §1–§5 全链路。  
> 读完本文，你可以在局域网内启动服务端、让桌面端连上去、注册账户后所有数据自动存到服务端。

---

## 一、架构总览

```
┌─────────────────────────┐         LAN / 本机          ┌──────────────────────────┐
│   芙洛理桌面端 (Flori.exe)  │  ←─── HTTP REST + WS ───→   │   芙洛理服务端 (node)       │
│                         │                              │                          │
│  Cloud (REST/WinHTTP)   │  POST /auth/register         │  §1 Auth (JWT)           │
│  Realtime (WS/Winsock)  │  POST /auth/login            │  §2 Sync (拉+合+推)      │
│                         │  GET  /sync/all              │  §3 Realtime (自习室)    │
│  RoomView  §3           │  PUT  /sync/all              │  §4 Columns (公共专栏)   │
│  RoadmapView §4         │  WS   /ws  (auth/presence)   │  §5 Media (资源库)       │
│  MediaView  §5          │  GET  /columns               │                          │
│                         │  GET  /media/list            │  data/ 目录持久化        │
│  accounts/ 本地缓存     │  POST /media/upload          │                          │
└─────────────────────────┘                              └──────────────────────────┘
```

**数据流方向：**
- **上行**（客户端 → 服务端）：勾选任务、写专栏、上传资源、发聊天、发在场状态
- **下行**（服务端 → 客户端）：同步拉取、在场成员列表、聊天消息、公共专栏、资源列表

**本地优先原则：** 服务端不开 / 断网时，桌面端一切照旧，全部功能走本地文件，不弹错不卡界面。连上后自动同步。

## 二、启动服务端

### 2.1 前置条件
- Node.js 18+（项目零第三方依赖，无需 `npm install`）

### 2.2 启动

```bash
cd Server
node server.js
```

看到以下输出即成功：
```
[i] 芙洛理服务端启动 → http://0.0.0.0:8787
[i] 数据目录: .../Server/data
[i] 演示账户: demo (已就绪)
```

服务端监听 `0.0.0.0:8787`，即**所有网络接口**都可访问（本机 + 局域网）。

### 2.3 环境变量（可选）

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `FLORI_HOST` | `0.0.0.0` | 监听地址 |
| `FLORI_PORT` | `8787` | 监听端口 |
| `FLORI_DATA_DIR` | `Server/data` | 数据目录 |
| `FLORI_SECRET` | 自动生成 | JWT 签名密钥（多机部署需一致） |
| `FLORI_ACCESS_TTL` | `7200` | 访问令牌有效期（秒） |
| `FLORI_REFRESH_TTL` | `2592000` | 刷新令牌有效期（秒） |

示例：换端口启动
```bash
FLORI_PORT=9000 node server.js
```

### 2.4 验证服务端

```bash
# 健康检查
curl http://127.0.0.1:8787/health
# 预期: {"ok":true,...}

# 跑冒烟测试（46 项全绿 = 通过）
cd Server && node tools/smoke.js
```

## 三、配置桌面端连接服务端

### 3.1 同机访问（默认，零配置）

桌面端默认连 `127.0.0.1:8787`。只要服务端在本机跑着，桌面端启动后自动连上，无需任何配置。

### 3.2 局域网访问（重点）

**场景：** 服务端在 A 机器跑，桌面端在 B 机器跑。

**步骤：**

1. **在 A 机器（服务端）上查 LAN IP：**
   ```bash
   # Windows
   ipconfig
   # 找「以太网适配器」或「无线局域网适配器」下的 IPv4 地址
   # 例如: 192.168.1.100
   ```

2. **在 B 机器（桌面端）上编辑配置文件：**

   配置文件路径：`<桌面端目录>/accounts/cloud-config.json`

   如果不存在，手动创建：
   ```json
   {
     "host": "192.168.1.100",
     "port": 8787,
     "secure": false,
     "enabled": true
   }
   ```

   把 `host` 改成 A 机器的 LAN IP。

3. **启动桌面端** → 它会读 `cloud-config.json`，连到 `192.168.1.100:8787`。

4. **防火墙：** 如果连不上，在 A 机器上放行 8787 端口：
   ```powershell
   # Windows PowerShell (管理员)
   New-NetFirewallRule -DisplayName "芙洛理服务端" -Direction Inbound -Port 8787 -Protocol TCP -Action Allow
   ```

### 3.3 配置文件字段说明

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `host` | string | `127.0.0.1` | 服务端地址（IP 或域名） |
| `port` | number | `8787` | 服务端端口 |
| `secure` | bool | `false` | 是否 HTTPS（自托管通常 false） |
| `enabled` | bool | `true` | 是否启用云同步（false = 纯单机模式） |

## 四、注册账户 & 数据上云

### 4.1 注册流程

1. 启动桌面端
2. 进入账户管理 → 注册新账户
3. 输入用户名 + 密码 → 桌面端调 `POST /auth/register`
4. 注册成功 → 自动登录 → 获取访问令牌 + 刷新令牌
5. 令牌存到 `accounts/<用户名>/cloud-session.json`

### 4.2 演示账户

服务端预置了演示账户：
- **用户名：** `demo`
- **口令：** 不在文档中登记（S0-3 去密）。查看 `Server/src/config.js` 的 `DEMO_PASS`；
  对外分发前请用环境变量覆盖：`set FLORI_DEMO_PASS=你的强口令` 后再 `node server.js`。

演示账户拥有管理员权限（可上传媒体、管理白名单）。

### 4.3 数据如何存到服务端

登录成功后，数据分五条通道存到服务端：

| 通道 | 触发时机 | 数据内容 | 服务端存储位置 |
|------|----------|----------|----------------|
| **§2 Sync** | 登录后自动 + 每次改动后防抖 2.5s | 六大数据块（档案/清单/打卡/复盘/专栏/设置） | `data/users/<uid>/*.flori.json` |
| **§3 Realtime** | 进入自习室 | 在场状态 / 聊天消息 | `data/room-chat.json`（聊天持久化） |
| **§4 Columns** | 进入专栏页 | 公共专栏列表（只读拉取） | `data/columns.json` |
| **§5 Media** | 进入资源库 | 资源列表（只读拉取）+ 上传 | `data/media/<kind>/` + `data/media.json` |
| **§2 Sync** | 退出时 | 最后一次冲刷 | 同上 |

**关键：** 桌面端的本地数据（`accounts/<用户名>/` 下的文件）始终是完整副本。服务端是「云端备份 + 多端同步 + 公共社交」的增强层，不是唯一存储。

## 五、三视图云端接入说明

### 5.1 自习室（RoomView · §3）

**接入内容：**
- 进入自习室 → 自动加入房间 `public` → 上报在场状态
- 实时接收：其他成员在场列表 / 公共聊天消息 / 背景音乐元数据
- 上行操作：发送聊天 / 更新在场状态（专注中/暂停/在线）

**离线降级：** 服务端不开时，自习室照常可用（计时、统计、历史记录全是本地），成员列表和聊天显示「离线」占位。

**已知限制：**
- 聊天输入为极简 ASCII 键位（无 IME），中文输入需客户端后续接入 IME
- 背景音乐只显示元数据，实际播放需客户端接入 XAudio2

### 5.2 专栏（RoadmapView · §4）

**接入内容：**
- 进入专栏页 → 自动拉取服务端公共专栏（`GET /columns`）
- 公共专栏显示在私有专栏下方，支持点赞
- 有人发帖/编辑/点赞/评论 → 服务端广播 `col:changed` → 客户端自动重拉
- 私有专栏（本地编辑）不受影响，照常增删改

**离线降级：** 服务端不开时，公共专栏区显示「离线」，私有专栏正常编辑。

### 5.3 资源库（MediaView · §5）

**接入内容：**
- 进入资源库 → 自动拉取服务端资源列表（`GET /media/list`）
- 云端资源显示在本地资源下方，按类型（视频/音乐/图片）标记
- 有上传权限的用户（白名单）显示「↑ 上传」按钮 → 弹出文件选择器 → 上传到服务端
- 自己上传的资源可删除

**离线降级：** 服务端不开时，云端资源区显示「离线」，本地资源（`assets/media/`）正常浏览和打开。

**上传权限：** 默认只有演示账户 `demo` 可上传。其他用户需演示账户将其加入白名单（`POST /media/whitelist`）。

## 六、与客户端更新分工

以下事项由客户端团队后续完善（不影响当前云端接入功能）：

| 事项 | 当前状态 | 后续方向 |
|------|----------|----------|
| 聊天 IME 输入 | 极简 ASCII 键位 | 接入 Win32 IME 或 EDIT 控件 |
| 背景音乐播放 | 只显示元数据 | 接入 XAudio2 / Media Foundation |
| 公共专栏发帖/编辑 | 只读 + 点赞 | 接入编辑器（复用私有专栏的 Win32 EDIT 弹层） |
| 评论展示 | 点赞已接入，评论 API 已就绪 | 客户端加评论列表 UI + 输入框 |
| 云端资源在线预览 | 只显示元数据 | 接入 `GET /media/file/:id` 流式播放 |
| 设置页端点配置 | 手动编辑 cloud-config.json | 加设置页 UI（host/port/enabled 输入框） |

## 八、故障排查

**Q: 桌面端一直显示「离线」？**
- 检查服务端是否在跑：`curl http://<host>:<port>/health`
- 检查 `cloud-config.json` 的 `host` 和 `port` 是否正确
- 检查 `enabled` 是否为 `true`
- 检查防火墙是否放行端口

**Q: 注册成功但登录后数据没同步？**
- 同步在后台线程异步执行，登录后等 2-3 秒
- 检查 `cloud-session.json` 是否有 `accessToken`
- 查服务端控制台是否有错误日志

**Q: 自习室成员列表不更新？**
- WS 连接需要先通过 auth 认证（桌面端自动处理）
- 确认两个客户端加入了同一个房间（默认 `public`）
- 查服务端控制台是否有 WS 连接日志

**Q: 上传资源提示「无上传权限」？**
- 只有白名单内的用户可上传
- 用演示账户 `demo` 登录，或让演示账户把你的用户名加入白名单
- 加白名单 API: `POST /media/whitelist` body `{"user":"你的用户名","add":true}`
