> 提炼自 `DesktopApp/docs/用户审美偏好与动效铁律.md`（概念 0–12 滚动共识）。
> 本精简版**只保留接手概念 12 必须知道的**；完整版（含全部 12 个概念背景）请回原文件查阅。

## A. 通用红线（任何动效概念都适用）

1. **创新第一、非大众化**：拒绝 SaaS 蓝白渐变 + 圆角卡片那套，要有辨识度与创意。
2. **有意义 + 实用价值优先**：不能为动效而动效；动效须服务于"让颜色 / 图形 / 功能更直观"。
3. **现代感、艺术现代化**：弃用「古老」有机自然形态（年轮 / 树 / 生长）；向往 Linear / Vercel 式克制工程数据美学。
4. **克制、零辉光、零 bloom**：流光因夸张辉光被否、圆球光晕 cliché。用色深 / 笔触 / 描边表达，不用加性光球。
5. **【最高优先级】信息可视化优先、实用性优先**：动效必须让数据**直观可读**，不能只是好看。图表本体（坐标轴 + 数值刻度 + 标签 + 可读几何）先于风格层；交互要能**直接获取信息**（框选→实时聚合读数）；拒绝「艺术有趣但读不出数据」的纯氛围表达（弦之鉴）。
6. **真实操作驱动、确定可控、非游戏**：拒问答 / 计分 / 抽测 / 输赢；动力学须阻尼收敛，不失控乱跑、不 idle 空浮。
7. **落真实界面**：看得见加在哪（mock 真实 chrome / tabs）。
8. **形态美感优先、告别方块堆叠**：拒绝柱状 / 色块 / 方块堆叠；改用有机曲线、细线、点阵、连续面、拓扑网等更精细几何（仍须零辉光）。
9. **配色必须讲究（和谐、克制、有层次）**：拒绝多硬色块同屏撞色；采用「单主色 + 灰度层次」或「协调类比色」；信息维度靠明度 / 饱和度 / 大小 / 位置区分。
10. **放弃时间轴 / 时序母题**：弦（时序弦波）、层积（时序岩芯）连续失败；新概念必须**非时序**，转向空间关系网 / 结构平衡 / 知识拓扑 / 形态映射。
11. **信息载体必须有足够密度**：拒绝稀疏采样插值出「大而空」的连续场（气脉死因）；要么高密度离散元素，要么不用连续场。
12. **形态边界须自然**：拒绝硬长方形截断；优先圆形 / 放射 / 有机 / 全幅深底漂浮。

## B. 概念 12 已确认方向（v2，唯一基线）

- 星海**高密度**（368 星 / 736 连线）、全幅深底 + 暗角、无硬框；
- **三通道数据着色**：色相 = 学科来源、纯度 = 难度（高=难）、明暗 = 掌握度（高=亮）—— 即约束⑰「数据着色豁免」的合法应用；
- 点星 → **正常考点卡**（320×240）**弹簧弹入**（`scale` 过冲，无飞出 / 旋转 / 漂浮）；
- 卡正面 **三按钮**（点亮 / 收入图谱 / 翻面）+ 学科信息；背面 `rotateY` 翻面看真题；
- 图谱 **非强制常驻**：拖入或按钮收卡，可 × 关闭，不 pinned；
- 顶部 KPI + 悬停精确探针面板（题型 / 来源 / 难度 / 掌握度）。

## D. 关键约束（锁定记忆）

- **约束⑭（通过配方即新基线）**：概念 10「考点星图」获认可，其配方作为后续概念新基线——非时序 + 单主色（墨青）+ 明度层次编码掌握度 + 细线拓扑网（线粗=关联强度）+ 力导向确定性布局 + 顶部 KPI + 悬停精确面板 + 真实操作驱动。概念 8 弦 / 9 层积 / 11 气脉流转**正式摒弃**，仅概念 9 留作「负面对照教材」。
- **约束⑰（数据着色豁免）**：当且仅当颜色用于**系统性编码数据维度**（而非装饰性撞色）时允许多色相。每学科=一个协调色相族（非彩虹乱炖）；饱和度由难度调制、明度由掌握度调制；整体克制、不刺眼、**零辉光**。
- **约束⑲（去按钮优先，但有限度）**：能用拖拽/键盘/悬停完成的交互尽量不用可见按钮；**然而概念 12 最终用户在 v2 回到了"正常卡片 + 按钮"**，勿机械执行"彻底去按钮"。
- **约束㉕（多变换拆独立层）**：若未来确需"飞出 + 3D 翻转 + 悬浮"，务必把每种变换拆到独立 DOM 层（入场 / 漂浮 / 偏转 / 翻面），勿堆在同一 `preserve-3d` 嵌套里——这是 v5 的技术教训（虽 v5 整体被否，但该工程结论仍成立）。
- **约束㉖（最重要）**：**已认可版本勿在其上堆新风格层；连续否定某方向时，优先回退到上一认可版，而非继续打补丁。** 概念 12 的 v3→v5 连续三版加层即反面教材。

## E. 操作红线（动手前必看）

- 仅改 `docs/识海星砂/`；**绝不碰** 看板娘层 / `App.cpp` / `TopBar.cpp` / `Store.*`；
- 提交只 `git add` 本次新增 / 修改文件，**勿 `git add -A`**（曾因误 add 删光 `src/`，见通用铁律）；
- headless 只验"能渲染 / 零报错 / 数值对"，**任何审美 / 手感改动必须由用户在真机浏览器确认**；
- 每次迭代**先记开发日志再改代码**，并**滚动总结用户反馈**防创意偏离。
