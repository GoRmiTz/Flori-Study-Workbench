## 0. 一句话结论

客户端**比注释看起来完成度高得多**：几乎所有「服务端待接入」的占位 UI，代码其实已经消费云端 / WebSocket 数据。真正的缺口只剩少数几项（档案同步、聊天中文输入、背景音乐后端、公共专栏渲染核对）。**最该做的是：清理过时注释 + 按已对齐的契约点亮剩余几处，而不是重写前端。**

## 二、真实功能缺失（按优先级）

### P0（对接必做，否则数据不通）
1. **契约已对齐，但需联调验证**
   - 客户端用 `PUT /sync/all?mode=merge` + `GET /sync/all`；服务端 `routes/sync.js` 正是这两个端点（含 `mode=merge` 分块合并，`core/sync.js` 的 `BLOCKS[].merge`）。
   - **注意**：`服务端需求清单.md` 第 2 节建议的是「逐块端点 `/sync/checkin?date=` 等」，**与现契约不同**。以代码（`sync.js` 的 `/sync/all` + `Cloud.cpp` 的 `SyncNow`）为准，不要去实现需求清单里那套逐块接口。
   - 同步载荷 schema 见 `服务端需求清单.md` §0 的 `*.flori.json`：六块 `checkin/focus/items/journal/rhythm/settings`，客户端 `ExportAll/ImportAll` 与 `BuildPayload/ApplyPayload` 复用同一结构。

2. **账户体系最终切换**
   - 现在 `AccountStore` 本地注册后「镜像」到云端（`MirrorAccount`），云端账户优先；但 `accounts.json` 的本地记录仍是权威源之一。交接时确认：多端登录 / 会话过期 / 踢下线 三条路径在真实服务端下行为正确（`Cloud::RefreshToken`/`Logout` 已接，需真服务端压测）。

### P1（体验闭环，建议本批做）
3. **「我的」档案未上云**（`ProfileView`）
   - `bio/major/school/birthday/gender` 仅落本地 `profile.json`，未走服务端 `users`（`/auth/me` 之类）。换设备后「我的」资料丢失。
   - 客户端对接点：`AccountStore::Instance().SaveProfile` 后补一次 `Cloud` 推送；`OnEnter` 时若已登录则拉取覆盖本地。

4. **自习室公共聊天输入框是 ASCII 占位**（`RoomView.h:165` 注释明示）
   - 当前聊天输入为「极简 ASCII 占位；CJK/IME 输入是客户端 UI 更新项」。收发逻辑（`SendChat`/`chat:msg` 下行）已通，**但中文输入法编辑态没接**，用户打不出中文。
   - 这是客户端 UI 任务（非服务端），复用现有 `EditProc` 子类化 + IME 方案即可（参考 `ManageView`/`ProfileView` 的 EDIT 代理）。

5. **背景音乐 XAudio2 后端未实现**（`RoomView.cpp:634,754`）
   - 服务端已给 `music:meta`/`music:list`，客户端只显示曲名占位。需落地本地音频播放（XAudio2 / Media Foundation），把 `music:list` 的流地址接进去即播。

### P2（增强，可延后）
6. **公共专栏列表渲染核对**（`RoadmapView`）
   - 已调 `GetColumns` 并设 `m_pubLive`，但当前多为空状态占位文案（「还没有公共专栏…」）。需确认：拉回的公开专栏数组是否真的画进列表卡片 + 点赞/评论交互是否走通。建议补一个联调断言或截图自检 `--route roadmap --live`。

7. **推送 / 提醒**（§6）— 纯增强，MVP 可不做。

## 三、可优化发展点

### A. 工程债（交接前最该清）
- **清理过时「待接入」注释**：上述一、二里点名的文件，注释与代码事实不符，容易让接手者误判「还没做」而重复造轮子。建议统一改为「已消费云端 / WS，联调中」或删除。
- **截图自检加自动 diff**：现有 `--shot` 仅验证不崩溃（EXIT=0）。建议加一张基线 PNG 做像素级 diff 或至少结构断言，防回归（尤其 EDIT 类改动容易悄悄破版）。

### B. 产品体验
- **非演示账户首页「今日速览」空态**：新账户 `items.json` 不存在 → `LoadItems` 回退空 `checklist` → 今日速览空白且无引导。建议在空态加一句「去『自定义打卡项』添加你的每日安排」，与演示账户体验对齐。
- **资料推荐 / 总线路图内容下发**：目前硬编码在 `Data.cpp`（`Content::Get()`）。若要做运营可改内容，应改为「本地缓存优先 + 后台拉取服务端 CMS」（需求清单 §4），但 MVP 阶段本地内容已能跑通，非紧急。
- **打卡项完成统计的「休息」豁免**：`HomeView::RefreshToday` 已对 `tag==L"休息"` 不计入统计，逻辑正确；若后续加更多豁免标签（如「弹性」），建议在 `CheckItem` 加显式 `excluded` 布尔而非靠 tag 字符串匹配。

### C. 性能
- 当前 6 视图 + 实时 WS + 后台同步线程，资源占用低；`Store` 每次写盘都 `MarkDirty` 防抖 2.5s 上推，合理。无显著瓶颈。
- 唯一隐患：`RoomView` 实时 `presence` 高频广播时，`Dispatch` 在后台线程写受锁缓冲 + 置 `m_netDirty`，`Update` 每帧消费快照——需确认 presence 频率（服务端 30s 心跳 + 进出房事件）不会造成卡顿，联调时压一下。

## 四、AI 味评估（减少「生成感」）

> 评估对象：**最终用户可见的文案与界面语言**，不含开发日志（日志面向工程师，详细是优点）。
> 判定标准：是否像「AI 套模板产出」——英文关键词+中点+中文标签、鸡汤式金句、pretentious 外来词、字间距不一致等。

### 已修（本轮 贰拾肆，已落地编译通过）
| 位置 | 原 AI 味文案 | 改为 | 性质 |
|------|------------|------|------|
| `Data.cpp` 封面三句 | 「这不是一份待办清单，而是一份正在被填写的档案。」「每一次勾选，都是给未来自己的盖章。」「从今天起，把自律与规划归档于此。」 | 「先把今天要做的，摊开看一眼。」「勾掉一项，就少操一份心。」「没做完也没事，明天接着来。」 | 鸡汤金句 → 平实口语 |
| `Data.cpp` subtitle | `自律 · 规划 · 专注，一处归档` | `打卡、专注、复盘，都记在这一处。` | slogan → 说明 |
| `Data.cpp` dossierNo | `DOSSIER · 自律档案` | `自律档案` | 外来 pretentious 词 → 直白 |
| `CoverView` 进入区 | `档案已就绪` / `回车 / 空格 亦可直接进入` | `都准备好了` / `回车或空格，也能直接进` | 机器 status → 人话 |
| `Data.cpp` 8 个模块 meta | `CORE · 每日` / `LIVE · 实时` / `DATA · 统计` … | `每日` / `实时` / `统计` … | 英文关键词+中点 → 纯中文 |

### 待你定夺（同类 AI 味，但属于设计系统，需你拍板再扫改）
1. **`SECTION · ××` 小标题眉**（约 30 处，跨 Checkin/Dash/Materials/Roadmap/Profile/Media/Video/Room）
   - 例：`SECTION · 每日执行档案`、`SECTION II · 功能模块`、`SECTION · 公共聊天（实时）`。
   - 全大写英文 `SECTION` + 中点 是典型设计模板痕迹。可改为纯中文眉（`每日执行档案` / `功能模块` / `公共聊天`），或保留作设计语言一致性元素——**取决于你是否把它当品牌标识**。
2. **模块名字间距不一致**（`Data.cpp` modules[].title）
   - `自 习 室` / `仪 表 盘` / `资 源 库` 是 1 个全角空格，`专　　栏` / `我　　的` 是 2 个全角空格，明显是手工不一致（AI/人工拼接痕迹）。
   - 若保留「字间距」美术字风格，应统一成同一种间距；若不要这种风格，直接去掉空格即可。当前未动，因涉及卡片视觉，需你确认。

### 明确不是 AI 味（保留，勿改）
- **资料推荐清单**（`Data.cpp` materials）：含具体老师名（粉笔980、站长申论、花生十三、高照、网友红领巾）、真实链接（夸克/腾讯文档/学习强国）、预算区间——是真人考公经验，信息密度高、可信，正是产品价值，**不要「润色」成通用话术**。
- **总线路图 / 月历 / 决策路径**：与用户实际备考方案强绑定（国考 11.29、湖南省考 3 月中旬、决策点 2027.4），是真实个人计划，非模板。
- **空状态引导文案**（如「还没有专注记录。开始一次专注，时长会自动计入档案。」）：口语、具体、有帮助，是好的产品文案，保留。

## 五、给对接同学的交接备注（别重做）

1. **不要重写前端**：所有占位 UI 的布局、状态位（`m_membersCard`/`m_chatCard`/`m_pubLive`/`m_netLive` 等）都已就位，后端按契约返回数据即可点亮。
2. **契约以代码为准**：`/sync/all?mode=merge`（非需求清单里的逐块端点）；REST 同端口同源 Bearer；WS 网关 `auth` 为连接首帧，客户端帧须掩码（已手写 RFC6455）。
3. **本地优先原则不变**：UI 线程只写文件 + 置原子 dirty 标记，网络 IO 全在后台线程（`Cloud::Worker` / `Realtime::Thread`），勿把网络调用搬进渲染循环。
4. **账户隔离**：数据根按 `AccountStore::CurrentRoot()`（本地）映射到服务端 `user_id`（云端），六数据块均按 `user_id`+日期键隔离。
5. **已修的输入框方案**（隐藏 1×1 透明 EDIT 代理 + `WS_EX_TRANSPARENT` + `HideCaret` + 自绘 D3D 光标）是跨视图标准做法，新增输入框请复用，别再引第三方 UI 库。
6. **构建 / 自检**：`source tools/msvcenv.sh && cmake --build build --target Flori`；截图 `--shot <png> --route <id> [--at s] [--dark] [--scroll px]`；日志 `flori.log`；契约测试 `tools/ws_contract_test.cpp`。
