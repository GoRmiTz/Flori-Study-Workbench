# 芙洛理 Flori · 服务端开发需求清单

> 面向服务端 AI 接手方。本文描述桌面端（原生 Windows C++ / D3D11+D2D）目前在「框架期」以**本地占位**呈现、需后端才能闭环的能力。
> 客户端代码已全部编译通过；服务端只需要补齐下列能力，并通过约定好的接口与客户端对接，即可把占位升级为真实功能。
>
> 现状一句话：客户端所有数据**当前落本地文件**（`build/accounts/<账户>/` 下 `checkin.json / focus.json / items.json / journal.json / rhythm.json / settings.json`），账号也是**本地注册**（FNV-1a 哈希存 `accounts/accounts.json`）。没有任何网络依赖。

---

## 0. 客户端数据模型（后端需对齐的契约）

客户端导出的标准备份文件 `*.flori.json`（`CheckinStore::ExportAll`）即**各数据块的权威 schema**，后端同步接口应直接复用同一结构：

```json
{
  "app": "FLORI",
  "version": 1,
  "account": "<账户名>",
  "exportedAt": "2026-08-04T23:00:00",
  "checkin":  { "YYYY-MM-DD": { "任务标题": 0/1, ... } },
  "focus":    [ { "id":"", "date":"YYYY-MM-DD", "start":"HH:MM", "end":"HH:MM", "tag":"主线", "minutes":25 } ],
  "items":    { "daily":[ CheckItem ], "sat":[ CheckItem ], "sun":[ CheckItem ] },
  "journal":  { "YYYY-MM-DD": { "summary":"今日做了什么", "next":"明日三件事" } },
  "rhythm":   { "YYYY-MM-DD": { "wake": <分钟OfDay 0..1439>, "sleep": <分钟OfDay> } },
  "settings": { "dark": false }
}
```

`CheckItem` 结构（打卡项）：`{ id, slot(时段,如"07:00"), title, tag(主线/英语/申论/常识/作息/手绘…), minutes(时长), link, folder, done }`。

**所有接口应以「按账户隔离」为前提**，与客户端 `AccountStore::CurrentRoot()` 的账户目录一一对应。

---

## 1. 用户中心 & 鉴权服务（Auth）【P0 基础】

- **对应客户端占位**：`src/app/AccountStore.*`（注释明写「纯本地存储，无云端依赖」）、`src/views/LoginView.cpp`（本地注册/登录，FNV-1a 哈希）。
- **需解决**：把本地账号升级为真实账号体系，支持多端登录、安全存储密码、会话管理。
- **核心能力**：
  - 注册 / 登录 / 退出 / 找回密码
  - 服务端密码哈希（argon2/bcrypt，替代客户端 FNV-1a）
  - 会话管理：JWT / 刷新 token；多端登录（桌面 / 未来 Web / 移动）
  - 账户隔离映射到服务端 `user_id`（客户端后续用 `<user_id>` 替代 `<账户名>` 做数据根）
  - 可选：第三方登录、邮箱/手机校验
- **客户端对接点**：`AccountStore` 的 `Login/Register/QuickLogin/Guest/Logout/HasSession` 将改为调用服务端；`session.json` 改存 token。`App::Initialize` 中 `AccountStore::Init()` 逻辑不变，仅内部实现切换。
- **建议接口**：`POST /auth/register`、`POST /auth/login`、`POST /auth/refresh`、`POST /auth/logout`、`GET /auth/me`。
- **优先级**：最高（其他所有服务端能力都依赖它）。

---

## 2. 数据同步服务（Sync）【P0】

- **对应客户端占位**：`src/app/Store.*` 全部本地落盘（`archive/`、` accounts/<name>/`）；`CheckinStore::Reload()` / `SaveItems` 等只操作本地文件。
- **需解决**：把 6 个数据块（checkin/focus/items/journal/rhythm/settings）从「纯本地」升级为「本地优先 + 云端同步」，支持换设备/重装后恢复。
- **核心能力**：
  - 6 数据块的服务端 CRUD（按 `user_id` + 日期键 / 文档）
  - 增量同步：客户端本地优先，联网后上推；拉取时合并增量
  - 冲突解决策略：建议 **last-write-wins**（带 `updatedAt` 时间戳）或向量时钟，客户端可容忍简单策略
  - 离线支持：服务端只需最终一致；客户端负责本地队列
  - 与 §1 Auth 共用 `user_id`
- **客户端对接点**：`ExportAll/ImportAll` 的 JSON 结构即为同步载荷格式；`CheckinStore` 各 `Load/Save` 方法后续可在成功写盘后触发一次静默上推。
- **建议接口**：`GET/PUT /sync/checkin?date=`、`GET/POST /sync/focus`、`GET/PUT /sync/items`、`GET/PUT /sync/journal?date=`、`GET/PUT /sync/rhythm?date=`、`GET/PUT /sync/settings`。
- **优先级**：高（与 Auth 并列基础；决定了「导出/导入备份」可进化为自动云同步）。

---

## 3. 实时通信服务（Realtime / IM）—— 自习室【P1】

- **对应客户端占位**：`src/views/RoomView.*`（注释「服务端依赖部分（背景音乐 / 在场成员 / 公共聊天）以本地占位呈现」）。具体占位：
  - 房间：`RoomView.cpp:428`「凭随机码加入他人的自习室（服务端待接入）」
  - 在场成员：`RoomView.cpp:569/582`「实时成员列表需接入服务端；当前为单机预览」
  - 背景音乐：`RoomView.cpp:618`「待接入」
  - 公共聊天：`RoomView.cpp:686/689`「公共频道需接入服务端后可用」
- **需解决**：让自习室成为真正的多人实时空间。
- **核心能力**：
  - 房间管理：服务端版公共/静音/冲刺房间；支持凭码加入他人房间（房间号/邀请）
  - **在场成员实时列表**（WebSocket presence + heartbeat）
  - **公共聊天频道**（消息广播 + 历史回拉 + 可选 @提醒/私聊）
  - **背景音乐**：服务端可提供曲目元数据/流地址（客户端用 XAudio2 播放，目前为占位）
  - 专注状态共享（可选）：房间内可见他人当前计时/科目
- **客户端对接点**：`RoomView` 已留 `m_membersCard / m_chatCard / m_musicY` 等布局与状态位，接到 WS 后填充即可；`App` 现有的 `AppSyncTheme`/`GoTo` 无需改。
- **建议协议**：WebSocket（`wss://`），事件：`room:join / room:leave / presence / chat:msg / music:meta`。
- **优先级**：中（增强体验，非核心闭环；但这是产品差异化卖点）。

---

## 4. 内容 / 专栏服务（CMS / Column）【P1】

- **对应客户端占位**：
  - `src/views/RoadmapView.*`：`RoadmapView.cpp:87/395/409`「公共专栏（服务端依赖）」占位——发布/点赞/收藏/评论、分区轮播、横向飞卡，需 WebSocket 公共服务端；本地「总线路图」已作为第一篇专栏落地。
  - `src/app/Data.cpp`：所有内容（考公方案、资料推荐清单、月历等）**硬编码**进源码 `Content::Get()`。
- **需解决**：把「作者发布内容 + 社区互动」与「可运营的内容下发」搬到服务端。
- **核心能力**：
  - **公共专栏系统**：栏目（分区）CRUD、文章发布/编辑/审核、点赞、收藏、评论、分区轮播、横向飞卡（参考 `RoadmapView.cpp:409` 的占位文案）
  - **内容下发（CMS）**：考公方案 / 资料推荐清单 / 月历等可服务端维护并下发，替代 `Data.cpp` 硬编码（客户端改为拉取 + 本地缓存）
  - 作者体系、审核流（可选）
  - 与 §3 实时能力共用 WebSocket（评论/点赞实时）
- **客户端对接点**：`RoadmapView` 的 `m_phY` 占位区块、专栏列表渲染逻辑已就绪，接数据后渲染；`Data.cpp` 的 `Content::Get()` 可改为「本地缓存优先，后台拉取服务端内容」。
- **建议接口**：`GET /columns`、`GET /columns/:id/posts`、`POST /posts`、`POST /posts/:id/like`、`POST /posts/:id/comment`。
- **优先级**：中（社区化核心；但 MVP 阶段本地内容可先跑通）。

---

## 5. 媒体存储与上传服务（Media）【P2】

- **对应客户端占位**：`src/views/MediaView.*`（注释「网页版依赖服务端上传（白名单授权），原生桌面端改为本地资源库」）；`MediaView.cpp:118/264`「上传 / 白名单依赖服务端」。
- **需解决**：把本地文件浏览升级为「上传 + 云端存储 + 白名单鉴权」。
- **核心能力**：
  - 上传接口 + **白名单**（文件类型 / 大小 / 安全扫描）
  - 对象存储接入（COS / S3），返回可访问 URL
  - 媒体元数据 + 转码（视频/音频缩略图、HLS 流）
  - 访问鉴权（私有资源签名 URL，防盗链）
  - 与 §1 Auth 对应：上传归属当前用户
- **客户端对接点**：`MediaView` 的 `ScanRecursive`（扫描 `assets/media`）可改为「拉取用户云端媒体列表」；点击打开可改为内嵌播放（XAudio2 / Media Foundation，目前 `MediaView.cpp:118/264` 已注释提示）。
- **建议接口**：`POST /media/upload`（带白名单校验）、`GET /media/list`、`GET /media/:id?sign=`。
- **优先级**：低（本地资源库已能跑通 MVP；上传为增强）。

---

## 6. （可选）推送 / 提醒服务（Push）【P3】

- **对应客户端占位**：打卡提醒、专注结束提醒目前纯本地（如需要）。
- **核心能力**：服务端推送打卡提醒、专注结束、专栏更新、好友动态。
- **建议**：WebPush / 移动端推送；桌面端可后期接 WebSocket 长连或系统通知。
- **优先级**：低（锦上添花）。

---

## 7. （可选）数据分析 / 社区榜服务（Analytics）【P3】

- **对应客户端占位**：仪表盘（`DashView`）统计目前仅本地聚合；无跨用户对比。
- **核心能力**：云端汇总跨设备数据、社区榜 / 好友对比、趋势洞察。
- **建议**：复用 §2 Sync 的数据，做只读聚合 API。
- **优先级**：低。

---

## 8. （可选）运营后台 / 配置下发（Admin）【P3】

- **核心能力**：内容下发（§4 CMS 运营面）、版本/公告/灰度、A/B。
- **优先级**：低。

---

## 交付建议（给接手 AI）

1. **先落地 §1 Auth + §2 Sync**（P0）：这是一切地基，且能直接把客户端的「导出/导入备份」升级为「自动云同步」。
2. **数据结构以 §0 的 `*.flori.json` 为权威 schema**，保证客户端导出导入与服务端同步零摩擦。
3. **实时类（§3 / §4 互动）共用一套 WebSocket 网关**，事件驱动。
4. **客户端已留好所有占位 UI 与状态位**，后端只需按上述「客户端对接点」返回对应数据，客户端即可在少改代码的前提下点亮功能；无需重写前端。
5. **账号迁移策略**：首版可保持「本地账户 + 可选绑定云端」双轨，降低风险；后续再切纯云端。

> 客户端工程约定（供对接参考）：构建 `source tools/msvcenv.sh && cmake --build build --target Flori`；截图自检 `./build/Flori.exe --shot <png> --route <id> [--at s] [--dark] [--scroll px]`；日志 `flori.log`。详细架构见 `docs/架构速记.md`、改动记录见 `docs/开发日志.md`。
