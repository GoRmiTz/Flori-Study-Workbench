# 时政练考模块 · 方案与路线

> 目标：用 AI（OpenAI 兼容 API）**每日定时**搜集/归纳最新时政，按考公题目样式出卷（单选/多选/判断），
> 编成符合《题目MD规范文档》的 `.md` 放入**指定文件夹**；软件读取后，以「专栏详情式居中卡片 + 右侧答题卡」
> 的形式呈现，支持选答、提交判分、解析展开。该引擎同时复用于**模考**（限时 + 倒计时 HUD + 出报告）。
> 本文档先定方案、路线、目标；**实现分步推进，不在本阶段写代码**。

---

## 1. 明确目标（Objectives）

| 编号 | 目标 | 验收口径 |
|---|---|---|
| O1 | 题目契约冻结 | 《题目MD规范文档》定稿，AI 产出与软件解析对齐，样例可双向校验 |
| O2 | 阅读器 + 答题卡（无 AI 也能跑） | 用手写 `.md` 即可打开试卷、选答、提交判分、看解析 |
| O3 | AI 定时出题 | 到点自动生成当日时政 `.md` 入指定文件夹，无需人工 |
| O4 | 模考复用 | 同一引擎加载限时卷，顶部倒计时，到点收卷出报告 |
| O5 | 学习闭环 | 成绩/薄弱知识点接入复盘（F-D7），不联网、不读窗内文本 |

## 2. 总体架构（决定路线）

```
                ┌───────────── 定时触发（QuizScheduler，仿 ReviewNudge）────────────┐
                │  每日 指定时刻(默认07:30) │ 检查 AI配置/时间窗/Token预算          │
                ▼                                                                │
   [AI 生成器 QuizGen]  ──复用看板娘已填凭据(Deepseek)──▶  OpenAI /chat/completions
        │  返回纯 MD（按规范）                                                    │
        ▼                                                                         │
   [指定文件夹]  accounts/<账户>/quiz/<类别>/YYYY-MM-DD.md   ◀─────────────────────┘
        │
        ▼
   [QuizParser] 零依赖状态机：.md → QuizDoc（见规范 §6）
        │
        ▼
   [QuizView]  居中试卷卡片（左：题干+选项，仿专栏详情） + 右侧答题卡（Q1..Qn 圆点/选中/跳转）
        │  选答 → 提交 → 判分 → 解析展开 → 得分
        ▼
   [QuizStore] 成绩/薄弱点落盘 accounts/<账户>/quiz_results.json
        │
        ▼
   [ReviewEngine]（F-D7）聚合薄弱知识点 → 复盘页
```

**复用点（不重复造轮子，全部来自现有代码）**
- AI 网络层：`src/kanban/KanbanAI.cpp` 的 `HttpPostJson`（winhttp 调 `/chat/completions`）。建议抽成 `src/net/AIClient.h` 共享；或按本项目「零依赖可复制」惯例就地复用 ~40 行。
- AI 凭据：**复用看板娘设置面板已填的 apiBase/apiKey/model**（单一来源，存本地面板不入库），答题模块默认走它，可加专属覆盖。
- 定时窗口：`src/core/ReviewNudge.cpp`（message-only 窗口 + 定时器）。
- 居中卡片样式：`src/views/RoadmapView.cpp::ComputePubPreviewRects`（max 720×620 居中弹层）。
- 模考倒计时/HUD：`src/core/ExamMode.cpp`（考场全屏 HUD + 倒计时 + 中断检测）。
- 落盘/报告：`src/app/Store.h` 的 `ExamReport` 结构、`CheckinStore` 读写。
- 复盘接入：`src/core/ReviewEngine.cpp`（注入练考表现）。
- 导航入口：`src/ui/TopBar.cpp` 加「练考」标签（route=`quiz`）。

## 4. 分阶段实现路线（逐步实现）

### Phase 0 — 规范与解析（地基，无 AI 依赖）
- 0-1 《题目MD规范文档》定稿（本交付物之一）。
- 0-2 `QuizParser`：零依赖状态机，`.md → QuizDoc`；纯函数 + 单元自测（用样例 md）。
- 0-3 样例 `sample-quiz.md`（本文件夹附），供手测解析。

### Phase 1 — 阅读器 + 答题卡（无 AI，用手写 md 验证）
- 1-1 `QuizView`：左侧试卷渲染（md-lite：标题/题干/选项按钮），右侧答题卡 strip（Q1..Qn 圆点、选中态、点击跳转）。
- 1-2 选答交互 + 提交 + 判分 + 解析展开 + 得分条 + 答题卡着色（✓绿/✗红）。
- 1-3 文件夹扫描：列出 `quiz/` 下可练试卷入口，点开进 1-1。
- 1-4 构建绿 + 像素回归（regress quiz 路由）。

### Phase 2 — AI 生成 + 定时调度（✅ 已落地，2026-08-15）
- 2-1 `QuizGen`（`src/quiz/QuizGen.{h,cpp}`）：零依赖 winhttp 调 `/chat/completions`；system+user 严格用规范 §7 模板；
      返回纯 MD 写 `accounts/<账户>/quiz/<类别>/YYYY-MM-DD.md`；自带解析自校验
      （先 `ParseQuizText`，失败则剥离 ``` 代码围栏重试，仍 0 题即报错）。
- 2-2 复用看板娘 AI 设置作默认凭据（`Store::LoadSettings().kanban`，含 `kanban_ai.json` 本地覆盖）；
      模型默认 `deepseek-v4-flash`，缺则回退该值。答题模块专属开关/时刻/类别/题量/RSS 由 `QuizScheduler::SetConfig` 暴露（Phase 4 接设置 UI）。
- 2-3 `QuizScheduler`（`src/quiz/QuizScheduler.{h,cpp}`）：仿 ReviewNudge，message-only 窗口 + 60s 定时器；
      每日默认 07:30 校验「AI 已配置 / 非访客 / 今日文件去重 / 30 分钟失败冷却」后，后台线程抓 RSS + 调 `QuizGen` 落盘；
      不阻塞主线程，UI 只读 `Last()`/`IsGenerating()`。
- 2-4（增强）`QuizRss`（`src/quiz/QuizRss.{h,cpp}`）：零依赖解析 RSS 2.0 `<item>` 与 Atom `<entry>`，
      抽 `title+description/summary` 拼 digest 注入 prompt。**默认源列表为空**（仅用模型知识保底），
      在 `QuizRss.cpp` 的 `kQuizRssDefaultFeeds[]` 填入可用 RSS/Atom 地址即启用（任一源失败跳过，不致命）。
- 2-5 UI 接入：QuizView 构造即启动调度器；列表头右上「立即生成今日时政」按钮（调 `KickNow()`）；
      显示生成状态（生成中 / 成功路径 / 失败原因）；生成完成自动重扫列表纳入新卷。

> 红线：请求体仅含 日期/类别/题量/可选RSS摘要，绝不喂窗内文本/路径/URL/私人数据；生成 .md 仅落本地。

### Phase 3 — 模考模式复用（✅ 已落地，2026-08-15）
> 决策 D5 选择「轻量复用」：模考为 **QuizView 内联倒计时 HUD + 收卷报告**，不强制进入全屏 ExamMode，
> 从而与未提交的看板娘层（Store.h/ExamMode.cpp）解耦，保持练考模块自包含（仅 stage 我方 quiz/ + QuizView.* 文件）。
- 3-1 `mode=exam` 识别 + 顶部倒计时 HUD：`OpenDoc` 读 `doc.meta["mode"]=="exam"`，解析 `duration`（分钟）初始化 `m_examTotalSec`；
      `Update` 每帧累积 `m_examElapsed += dt`，归零即 `Submit()` 自动收卷；HUD（`PaintExamHud`）显示「剩余 mm:ss」+
      进度条，剩余 ≤30%/≤10% 分别转黄/红，超时显示「已收卷」。
- 3-2 模考卷来源：`ScanQuizzes` 已枚举 `quiz/<类别>/*.md`，故 `quiz/模考/*.md` 自动成为「模考」类别；
      列表卡片对 `mode==exam` 显示印章色描边 + 「模考 · N 分钟」元信息与「进入模考 ›」入口。
      内置样例 `quiz/模考/2026-08-15-模考样例.md`（`duration: 30`）随 `SeedSampleIfEmpty` 落地，首次即用。
- 3-3 结束出报告：新增 `QuizReport` 结构（`src/quiz/QuizParser.h`）+ `ComputeQuizReport` 纯逻辑（无 Win32），
      汇总 得分/正确率/用时/计划/状态（完成·超时收卷）；`PaintExamReport` 在右侧面板渲染「模考报告」。
      **中断记录说明**：方案原文「记录中断（若进 ExamMode 全屏）」——本阶段为内联模式、未进全屏，
      故不追踪切窗中断（与 D5 轻量决策一致）；若后续需要中断检测，再接 `ExamMode` 全屏 HUD 复用其逻辑。
- 3-4 报告/得分复用既有判分：`Submit()` 仍调用 `quiz::IsCorrect` 判分，并额外生成 `QuizReport`；
      模考交卷按钮文案「交卷 / 重新模考」，练习卷为「提交 / 重新答题」。

### Phase 4 — 闭环与打磨（✅ 已落地，2026-08-15）
> 解耦结论（重要）：`ReviewEngine`/`CheckinStore` 位于**未提交**的 `Store.h`，仅提供「从 store 生成」入口、无注入练考表现的 API，
> 故深度接入复盘被阻断。本阶段改为**自包含落盘**：成绩写入 `accounts/<账户>/quiz_results.json`，
> 薄弱知识点由 QuizStore 独立聚合，并在 UI 暴露「薄弱考点」卡片，待看板娘层提交后即可无缝挂接 ReviewEngine。
- 4-1 成绩落盘 + 薄弱知识点（自包含）：
  - 新增 `src/quiz/QuizStore.{h,cpp}`：`QuizAttempt`（ts/dateKey/title/category/mode/total/correct/wrong/unanswered/accuracy/plannedSec/usedSec/timeout/weakPoints）、`QuizSettings`（enabled/hour=7/minute=30/category=时政/qcount=10/rss=true）。
  - `RecordAttempt` 追加写 `quiz_results.json`（`{attempts:[...]}`）；`TopWeakPoints(n)` 聚合错题库 `point` 计数降序取前 n。
  - `Submit()` 现已记录一次 `QuizAttempt`（weak 取自错题 `point`），并刷新列表底部「薄弱考点」卡片（`PaintWeakCard`）。
- 4-2 考试模式零打扰：
  - `QuizScheduler` 新增 `SetQuiet(bool)`（atomic 标志）+ `GetConfig(...)`；`MaybeStart` 自动路径在 `m_quiet` 时直接 return（手动 `KickNow` 不受影响）。
  - `QuizView` 进入模考即 `SetQuiet(true)`，交卷/关闭恢复 `SetQuiet(false)`。全局免打扰总开关位于未提交层，留待挂接。
- 4-3 设置 UI（自包含卡片）：
  - `QuizView` 列表头右上新增「设置」按钮（`m_setBtn`），点开全屏设置卡（`PaintSettings`）：每日出题开关、出题时刻（时/分 ±）、出题类别（切换）、每日题量（±）、抓取 RSS（开关）。
  - 任意改动经 `ApplySettings` → `SaveSettings(quiz_settings.json)` + `QuizScheduler::SetConfig(...)` 立即生效。
  - AI 凭据**不在此重复**：默认复用看板娘面板（Phase 2 已接 `kanban_ai.json` 本地覆盖）。
- 4-4 真机目视确认（仅提示，无法在此 headless 验证）：答题卡交互/拖拽/弹层手感、设置卡点按、薄弱卡片渲染须真机 GUI 确认；像素回归同 Phase 2/3 受未提交看板娘层影响暂不跑。

> 红线保持：请求体仅含 日期/类别/题量/可选RSS摘要，绝不喂窗内文本/路径/URL（见 Phase 2 §红线）。

## 5. 风险与缓解

| 风险 | 缓解 |
|---|---|
| AI 输出不守规范导致解析失败 | 规范 §6 容错跳过坏题；生成后跑一次解析自校验，失败重生成或告警 |
| 「最新时政」不够新 | D2 推荐 RSS 抓取；纯 LLM 作保底并在卷首标注"知识截止" |
| Token/成本失控 | 复用看板娘 Token 预算 + 时间窗；每日一题卷控制在 ~10 题 |
| 答卷卡交互复杂、headless 无法验 | 像素回归只保渲染零漂；交互/手感必须真机 GUI 确认 |
| 多账户数据串味 | D4 每账户隔离目录 |
| 隐私越界（AI 读到窗内文本） | 红线：生成请求体仅含 日期/类别/题量/可选RSS摘要，绝不喂窗内文本/截图/路径 |

## 6. 与主线其它模块关系
- **看板娘（F-D11）**：可调用 QuizView 在「好奇」状态提示"今天时政做了吗？"；AI 凭据同源。
- **复盘（F-D7）**：练考成绩/薄弱点汇入复盘，形成"练→评→补"闭环。
- **模考（F-D6）**：QuizView 的 exam 模式是其题目承载面，二者共用引擎。
- **专栏（No.04）**：展示样式借鉴其居中详情卡片，但答题卡为新增。
