# 05-A · 服务端需求清单（P0–P3）

> 继承自 `DesktopApp/docs/服务端需求清单.md`。面向服务端接手方，描述客户端当前以**本地占位**呈现、需后端闭环的能力。客户端代码已全部编译通过；服务端只需补齐下列能力并通过约定接口对接即可升级为真实功能。
> 现状一句话：客户端数据当前落本地文件（`accounts/<账户>/*.json`），账号本地注册（FNV-1a 哈希），无网络依赖。

---

## 0. 客户端数据模型（后端需对齐的契约）

客户端导出的标准备份 `*.flori.json`（`CheckinStore::ExportAll`）即**各数据块的权威 schema**，后端同步接口应直接复用：

```json
{
  "app": "FLORI",
  "version": 1,
  "account": "<账户名>",
  "exportedAt": "2026-08-04T23:00:00",
  "checkin":  { "YYYY-MM-DD": { "任务标题": 0/1, ... } },
  "focus":    [ { "id":"", "date":"YYYY-MM-DD", "start":"HH:MM", "end":"HH:MM", "tag":"主线", "minutes":25 } ],
  "items":    { "daily":[ CheckItem ], "sat":[ CheckItem ], "sun":[ CheckItem ] },
  "journal":  { "YYYY-MM-DD": { "summary":"今日做了什么", "next":"明日三件事" } },
  "rhythm":   { "YYYY-MM-DD": { "wake": <分钟OfDay 0..1439>, "sleep": <分钟OfDay> } },
  "settings": { "dark": false }
}
```
`CheckItem`：`{ id, slot(时段), title, tag(主线/英语/申论/常识/作息/手绘…), minutes, link, folder, done }`。
**所有接口以「按账户隔离」为前提**，与 `AccountStore::CurrentRoot()` 一一对应。

---

## 1. 用户中心 & 鉴权（Auth）【P0】
- **客户端占位**：`AccountStore.*`（本地存储）、`LoginView.cpp`（FNV-1a 哈希）。
- **需解决**：本地账号→真实账号体系，多端登录、安全存密、会话管理。
- **能力**：注册/登录/退出/找回；服务端哈希（argon2/bcrypt 替代 FNV-1a）；JWT/刷新 token；账户隔离映射到 `user_id`；可选第三方登录。
- **接口**：`POST /auth/register`、`POST /auth/login`、`POST /auth/refresh`、`POST /auth/logout`、`GET /auth/me`。
- **对接点**：`AccountStore` 的 Login/Register/QuickLogin/Guest/Logout/HasSession 改调服务端；`session.json` 改存 token；`App::Initialize` 中 `AccountStore::Init()` 逻辑不变，仅内部实现切换。

## 2. 数据同步（Sync）【P0】
- **客户端占位**：`Store.*` 全部本地落盘。
- **需解决**：6 数据块（checkin/focus/items/journal/rhythm/settings）从纯本地→本地优先+云端同步。
- **能力**：服务端 CRUD（按 user_id+日期键/文档）；增量同步；冲突策略 last-write-wins（带 updatedAt）或向量时钟；离线支持。
- **接口**：`GET/PUT /sync/checkin?date=`、`GET/POST /sync/focus`、`GET/PUT /sync/items`、`GET/PUT /sync/journal?date=`、`GET/PUT /sync/rhythm?date=`、`GET/PUT /sync/settings`。
- **对接点**：`ExportAll/ImportAll` JSON = 同步载荷格式；各 `Load/Save` 成功后触发静默上推。

## 3. 实时通信（Realtime / IM）— 自习室【P1】
- **客户端占位**：`RoomView.*`（房间/在场成员/公共聊天/背景音乐均以本地占位）。
- **能力**：房间管理（公共/静音/冲刺、凭码加入）；在场成员实时列表（WS presence+heartbeat）；公共聊天（广播+历史+@/私聊）；背景音乐元数据/流地址；专注状态共享。
- **协议**：WebSocket `wss://`，事件 `room:join / room:leave / presence / chat:msg / music:meta`。
- **对接点**：`RoomView` 的 `m_membersCard/m_chatCard/m_musicY` 布局已就绪，接 WS 填充即可。

## 4. 内容/专栏（CMS / Column）【P1】
- **客户端占位**：`RoadmapView.*`（公共专栏发布/赞/藏/评占位）；`Data.cpp`（内容硬编码）。
- **能力**：公共专栏系统（栏目 CRUD/文章/点赞/收藏/评论/轮播）；内容下发（CMS 替代 `Data.cpp` 硬编码）；作者体系/审核。
- **接口**：`GET /columns`、`GET /columns/:id/posts`、`POST /posts`、`POST /posts/:id/like`、`POST /posts/:id/comment`。
- **对接点**：`RoadmapView` 占位区块接数据渲染；`Data.cpp::Content::Get()` 改本地缓存优先+后台拉取。

## 5. 媒体存储与上传（Media）【P2】
- **客户端占位**：`MediaView.*`（上传/白名单依赖服务端）。
- **能力**：上传接口+白名单；对象存储（COS/S3）；元数据+转码；签名 URL 防盗链。
- **接口**：`POST /media/upload`、`GET /media/list`、`GET /media/:id?sign=`。

## 6. 推送/提醒（Push）【P3】
- 打卡/专注/专栏/好友动态推送；WebPush/移动端；桌面端后期 WS 长连。

## 7. 数据分析/社区榜（Analytics）【P3】
- 跨设备汇总、社区榜/好友对比、趋势洞察；复用 Sync 数据做只读聚合。

## 8. 运营后台/配置下发（Admin）【P3】
- 内容下发、版本/公告/灰度、A/B。

---

## 交付建议（给接手方）
1. 先落地 **§1 Auth + §2 Sync**（P0）：把"导出/导入备份"升级为"自动云同步"。
2. 数据结构以 **§0 `*.flori.json` 为权威 schema**，保证零摩擦。
3. 实时类（§3/§4 互动）共用一套 **WebSocket 网关**，事件驱动。
4. 客户端已留好所有占位 UI 与状态位，后端只需返回对应数据即可少改代码点亮功能。
5. 账号迁移：首版可"本地账户 + 可选绑定云端"双轨，降低风险。

> 客户端工程约定：构建 `source tools/msvcenv.sh && cmake --build build --target Flori`；契约测试 `./build/ws_contract_test.exe`；日志 `flori.log`。详细见 `03_源代码梳理/`。
