# 02-C · 练考与复盘系统

> 来源：`quiz/`、`core/ReviewEngine`、`core/ReviewNudge`、`core/FocusTracker`、`core/ExamMode`、`views/QuizView`。这是"内容真"与"买点闭环"的命脉，芙洛理必须完整继承并接 Godot 动效回传。

## 1. 题目格式契约（QuizParser）

`quiz/QuizParser.{h,cpp}`，命名空间 `lj::quiz`。**这是"内容真"的命脉**——所有题库/动效概念都依赖它。

- 结构：`QuizOption{key,text}`、`QuizQuestion{id,type,stem,options,answer,explain,point,difficulty,hasAnswer}`、`QuizDoc{title,meta,questions}`、`QuizReport{total,correct,wrong,unanswered,accuracy,...}`。
- **题目 .md 规范**：YAML frontmatter（`---` 包裹 `title/date/category/mode/duration/source/model`）+ `#` 卷标题 + `## Qn` + `- A.`~`E.` 选项 + `**题型**`/`**答案**`/`**解析**`/`**知识点**`/`**难度**`；解析支持多行续行，判断题映射"正确→A/错误→B"。
- `IsCorrect(q,selected)`：对 `answer`/`selected` 排序+去重后整体比较，**无序、支持多选**。
- UTF-8 零依赖自解码状态机：`Utf8ToWString`、`ReadFileUtf8`（去 BOM）。所有生成/抓取内容必须过 `ParseQuizText` 校验。

## 2. 题目来源（三路）

| 来源 | 文件 | 说明 |
| --- | --- | --- |
| AI 生成 | `QuizGen.cpp` | 复用看板娘 `winhttp`（`HttpPostJson`）调 `/chat/completions`，写 `accounts/<账户>/quiz/<类别>/YYYY-MM-DD.md`。请求体仅含 日期/类别/题量/RSS摘要 |
| RSS 保底 | `QuizRss.cpp` | `winhttp` GET + 极简 XML 抽取（RSS/Atom），默认源 `nullptr`→不联网、模型保底 |
| 本地存储 | `QuizStore.cpp` | 每账户隔离 `accounts/<账户>/quiz/<类别>/`；`RecordAttempt` 落 `quiz_results.json`；`TopWeakPoints(n)` 跨次聚合答错知识点 |

> AI 凭据单一来源 `LoadKanbanAIConfig()`（本地文件，不入库）。

## 3. 调度（QuizScheduler）
`QuizScheduler.cpp`：**仿 ReviewNudge**——message-only 窗口 + 60s `SetTimer`，默认 07:30 触发 `MaybeStart`→后台线程生成；校验链（AI 凭据 / `IsGuest` 跳过 / 今日已生成去重 / `SetQuiet` 模考零打扰 / 失败 30min 冷却）。

## 4. 复盘引擎（ReviewEngine / ReviewNudge）

- `ReviewEngine.cpp`：`DayReview{done,total,overallPct,focusMin,focusCnt,interrupts,journaled,weak,hint,lines}`；`ReviewWeakItem{tag,pct,total,target,gap()}`。`Generate(dateKey)` 从 CheckinStore 汇总，按 `PlanTargetPct`（行测85/申论80…）求 `实际<目标` 为薄弱项（gap 降序）；`CommitWeakToJournal` 写"明日三要事"。
- `ReviewNudge.cpp`：默认 **21:00** 托盘气泡 → `App::NavigateTo("review")`；`ExamMode::Running()` 不打扰；`reviewNudgeLast` 跨重启去重。

## 5. 专注 / 考场

- **FocusTracker（F-D1）**：每秒轮询前台进程+idle，满 60s 落 `focus.json`；`SetUserApps`/`SetEntApps` 分类；`Pause/Resume`（F-D3）。
- **ExamMode（F-D6）**：`Start(120)` 全屏顶部 HUD，1s 定时器，复用 FocusTracker 做中断检测（3s 宽限、`interrupts++`），`Finish` 累计 `effectiveSec` 并 `AddExamReport`。不锁系统。

## 6. 给芙洛理 / Godot 的关键提示

1. **数据核心留原生/服务端**：QuizParser 解析、QuizStore 落盘、QuizGen 出题、UTF-8 编解码不可搬进 Godot；Godot 只做"题目呈现 + 作答交互 + 回传标记"。
2. **IPC 契约雏形**（见 `01_架构设计` §3）：Godot 请求 deck → 原生回传 `QuizDoc`；作答后回传 `selected[]` 与 `mark(known/weak)` → 原生 `IsCorrect` 判分、`RecordAttempt` 写薄弱项、`ReviewEngine` 重算。
3. **闭环缺口（重要）**：芙洛理原生**仅单向"待巩固"**——`QuizView::Submit` 把错题 `point` 写入 `weakPoints`，**缺"标已会"掌握度反向衰减**通道。芙洛理须在 IPC 补齐 `mark:known` 衰减并由 `QuizStore` 持久化掌握度，否则动效（抽笺/舆图/墨显）失去数据驱动。
4. **动效买点依赖此回传**：概念 18–29 的"标已会/待巩固"闭环全在此层。
