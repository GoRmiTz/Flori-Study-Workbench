# 00 · 芙洛理 Flori · 项目总览与交接说明

> 本文件是「芙洛理」项目的总入口。先读它，再按 `README.md` 导航跳到细分文档。

## 1. 项目命名与由来

- **芙洛理（Flori）**：新项目名，寓意「自律之花（flor-）在理性（理性/律）中生长」。是「芙洛理 Flori」的继承与重构版本。
- **与原项目关系**：基于现有芙洛理代码库重新设计，全面集成 **Godot 4** 做动效/游戏性表现层，并针对用户已确立的视觉铁律做升级（亮色纸底、墨线主导、零辉光、信息可视化优先、买点/价值闭环）。

## 2. 产品定位（继承自芙洛理）

一款面向**考公/考研备考人群**的桌面端自律应用：
- 本地优先：不连服务端也能用（打卡 / 专注 / 复盘 / 练考 / 看板娘）。
- 云端增强（可选）：多端同步、实时自习室、公共专栏、媒体库。
- 核心闭环：**打卡 → 专注 → 复盘 → 练考 → 掌握度提升**。

## 3. 技术路线（核心决策）

| 层 | 芙洛理现状 | 芙洛理方案 |
| --- | --- | --- |
| 应用壳 | 原生 Win32 + D3D11/D2D，零依赖 | **原生壳保留**（账户/数据/云端/复盘/错题集/看板娘核心逻辑），零依赖 |
| 动效/游戏性 | 手写 D2D 自绘游戏循环（用户作为技术小白最累） | **Godot 4 子进程**（MIT，桌面原生导出 `.exe+.pck`），按需启动 |
| 通信 | 单进程内函数调用 | **IPC**：原生壳 ↔ Godot 子进程，行分隔 JSON（本地 TCP 127.0.0.1 或命名管道） |
| 视觉 | DOSSIER 暗/亮 | 亮色纸底 `#F6F2E9` + 墨线 + 零辉光 + 青绿 `#268678` 仅强调 |

**为什么选 Godot 而非 UE5**：MIT 无 royalty（UE5 年营收 >$1M 收 5%）、2D 是主场（比手写 D2D 省力一个数量级）、默认无光照天然贴墨线美学、桌面原生导出不碰 web。

## 4. 给新成员的交接手册

### 4.1 你接到的任务
从零用 **Godot 4 + 原生壳（沿用/重构芙洛理 C++ 核心）** 重建「芙洛理」。本包已把芙洛理的**功能、代码、日志、红线、服务端、概念想法**全部摸透并分文件夹归档，你无需重挖代码即可上手。

### 4.2 建议上手顺序
1. 读 `README.md` → 本文件 → `01_架构设计`（IPC 分层是核心）。
2. 按 `02_功能模块详述` 认领模块；数据模型以 `05_服务端需求/服务端需求清单.md` 的 `*.flori.json` schema 为权威。
3. 视觉/动效务必对齐 `04_开发日志与美学红线/用户审美铁律全集.md`（㉘–㉟）与 `视觉规范_芙洛理.md`。
4. 动效选题参考 `06_概念想法库`（概念 18–29 为「买点+价值闭环」方向的现成素材）。

### 4.3 开发环境（沿用芙洛理工具链，原生壳侧）
- Windows 10/11 x64；Visual Studio Build Tools（含 C++ 桌面开发）；CMake ≥3.21；Ninja；MSVC C++20 `/utf-8`。
- Node.js ≥18（服务端零依赖，不用 `npm install`）。
- Godot 4.x（独立安装，负责动效/游戏性子体验）。

### 4.4 红线（动工前必看）
- **数据/状态核心留在原生侧或服务端**；Godot 只做"演 + 收 + 回传标记"，绝不直接写业务数据库。
- **API 凭据绝不硬编码/入库**：看板娘等密钥走本地文件（见 `02_功能模块详述/看板娘与对话AI.md`）。
- **零辉光、克制、信息可视化优先、真实操作驱动、确定可控**：见铁律全集。
- **概念原型仅作想法，本次不开发**。
