# 06-B · 动效概念买点范式（选型标准）

> 用户在 2026-08-18 核心批评："看起来像无用的花瓶，欠缺怎么在软件中利用上、怎么成为买点"。本文件从**抽笺(27)/舆图(28)/墨显(29)** 提炼出"买点+价值闭环"范式，作为芙洛理动效选型的**硬标准**（对应铁律㉟）。

---

## 一、什么是"花瓶"（必须避免）

- 动效美但与学习功能脱节，用户看完不知道"这东西对我备考有什么用"。
- 只有展示、没有交互产出；或交互是"观察一座 3D 结构"（轨道旋转/缩放/飞入聚焦）但无学习价值。
- 正面范式（用户点名）：**抽卡项目**——"用户可以通过卡片获取知识，且富有娱乐性"。

## 二、买点闭环四问（每个动效必须答）

1. **落在软件哪里？** → 接 `QuizParser` 题库 / `ReviewEngine` 复盘 / 错题集 / 每日复习。
2. **买点/钩子是什么？** → 抽取惊喜 / 收集 / 仪式感 / 进度可视化 / 自适应复习。
3. **每次交互是否产生学习价值？** → 获取知识 / 复习 / 推进掌握度 / 入册入集。
4. **回传机制？** → 经 IPC 回传 `mark(known/weak)` → 原生落库（见 `01_架构设计` §3）。

## 三、三个现成范式（可直接用 Godot 实现）

### 范式 A · 抽笺（概念 27）— 抽卡式复习
- **循环**：点笺匣抽一笺 → 墨韵揭示考点(标题+精讲+真题引) → 标「已会/待巩固」→ 飞入「已习笺册」写复盘/错题集。
- **买点**：① 娱乐化随机复习（spaced repetition 抽卡包装）；② 装册进度可视化（已习 N 笺）；③ 待巩固加权重抽（自适应闭环）。
- **落点**：笺面来自 QuizParser 题目 .md；「已会」→ ReviewEngine、「待巩固」→ 错题集。

### 范式 B · 舆图（概念 28）— 信息可视化+回忆测验
- **循环**：点未勘区 → 出该考点勘测题 → 标「已掌握/待巩固」；掌握→覆盖率+1&相邻青绿涟漪。
- **买点**：① 顶部 KPI=疆域覆盖率%+七科进度条（信息可视化优先）；② 每次勘察=一次回忆测验；③ 待巩固进池+今日计数。
- **落点**：区域=QuizParser 题库分域簇；掌握→ReviewEngine；覆盖率→dashboard。

### 范式 C · 墨显（概念 29）— 显影复习+拓扑可视化
- **循环**：光标扫过→知识自淡墨显成浓墨（真实操作持续驱动）；点已显节点→阅卷卡→标已会/待巩固。
- **买点**：① 显影仪式感（确定可控非自跑）；② 主动浏览回忆（拓扑随光标实时长出）；③ 拓扑直接可读（节点大小=重要性、墨浓=掌握、细线=关联）。
- **落点**：节点=QuizParser 题库分域簇；标记→ReviewEngine/错题集/KPI。

## 四、Godot 实现映射（参考）

| 概念 | Godot 2D 实现 | 难度 |
| --- | --- | --- |
| 抽笺 | Control + Tween 抽卡状态机 + IPC deck/result | 低 |
| 舆图 | Control/多边形区域 + 点击勘测 + IPC | 低 |
| 墨显 | CanvasItem._draw 墨线 + shader 显影遮罩 + IPC | 低 |
| 织缕 | Line2D 织线 + 拖拽连点 + IPC | 低 |

均无需 3D，Godot 2D 主场，比手写 D2D 省力一个数量级。

## 五、选型 checklist（芙洛理动效负责人用）

- [ ] 是否回答"落在软件哪里"？(接 QuizParser/Review/错题集？)
- [ ] 是否有钩子让用户持续交互？(抽取/收集/仪式/进度？)
- [ ] 每次交互是否产生学习价值？(获取/复习/推进掌握度？)
- [ ] 是否经 IPC 回传 mark 落库？(数据闭环？)
- [ ] 是否过 ㉘–㉟？(亮色/换范式/买点/零辉光/信息可视化？)
