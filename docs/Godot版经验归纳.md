# Godot 版经验归纳（供 C++ 零依赖桌面端复用）

> 背景：芙洛理曾以「原生 C++ 壳 + Godot 4 子进程 + 本地 IPC（127.0.0.1:7821，行分隔 JSON）」路线开发，
> 现回归 C++ 零依赖桌面端（原「芙洛理 Flori」重制为「芙洛理 Flori」）。
> 本文件归纳 Godot 版**可复用的设计原则、视觉语言、动效铁律与踩坑**，供 C++ 桌面端直接落地，
> 不涉及任何 Godot 专属 API——它是一套「核心（状态/数据）与表现（渲染/动效）分离」的方法论。

---

## 0. 一句话总纲

**表现层只做"演 + 收 + 回传"，绝不持有业务数据与判分权。** 无论有没有 IPC，
"C++ 核心持有状态、渲染/动效层只读快照"这一分离原则都适用，且是后续所有铁律的源头。

---

## 1. 三条不可动摇的设计决定（IPC 三铁律）

即便不用 IPC，把"核心 ↔ 表现"换成"核心层 ↔ 渲染层"同样成立：

1. **判分权留宿主（核心层）**
   - 表现层拿到的"题"不含答案；用户作答后上报 *selected*，由核心层判 *correct* 再回传。
   - 红线：**绝不下发答案给表现层**。表现层永远不该知道标准答案是什么。
2. **KPI / 掌握度只由核心层驱动**
   - 表现层拿到的是核心层算好的 `mastery`，**不自行累加**掌握度。
   - 渲染层可以"显示"掌握度，不能"计算"掌握度。
3. **`known` 反向衰减**
   - 旧设计只有单向"标记待巩固"；必须补齐"标记为已掌握后随时间反向衰减"的遗忘曲线。
   - 掌握度是双向的：巩固会升，搁置会降。

---

## 2. 框架优先于游戏（最重要的一条弯路教训）

- 先有**软件框架**：`splash → home → 6 个业务页（打卡/专注/复盘/练考/分析/设置）`，
  **只有 GameSlot 一个槽位放游戏化探索**。
- 不要一上来堆游戏机制。**抽测 / 计分 / 对错 / 输赢 = 廉价小游戏感，已被明确否决。**
- 动效概念原型（弦/层积/气脉流转…）是"想法库"，不是软件本身；
  通过的配方才沉淀为基线，被否的正式摒弃，不要反复回退到被否版本。

---

## 3. 视觉语言（已验证的基线）

| 要素 | 规范 |
| --- | --- |
| 纸底 | 浅色 `#F6F2E9`（亮色纸感，非纯白） |
| 主色 | 青绿 `#268678`（可变；M1 默认 A 青绿 / B 朱赭 / C 靛黛） |
| 字体 | 衬线标题 + 等宽数字（numeric tabular） |
| 栅格 | 8px 基准栅格 |
| 辉光 | 适度，**bloom ≤ 0.3**，禁用"软圆辉光" |
| 配色 | **克制和谐**：单主色 + 灰度层次；维度靠**明度 / 大小 / 位置**区分，不靠硬撞色 |

**配色红线**：告别方块堆叠（用细线 / 点阵 / 连续面 / 拓扑网）；放弃时间轴 / 时序母题。

---

## 4. 信息可视化优先（最高优先级）

含数据的界面，**数据须先于动效可读**：

- 必须有**坐标轴 + 数值刻度 + 标签 + 可读几何**，不能只给一个"好看的形状"。
- 交互要能**直接获取信息**：
  - 框选区间 → 实时聚合读数；
  - 悬停 → 精确单点值面板。
- **通过基线（概念 10 考点星图）**：非时序 + 单主色(墨青) + 明度编码掌握度 + 细线拓扑网(线粗=关联强度)
  + 力导向确定性布局 + 顶部 KPI + 悬停精确面板 + 真实操作驱动(悬停高亮/点击弹簧脉冲/拖拽)。
- **被否的反面教材**：
  - 概念 8「弦」：艺术有趣但**无法直观获得信息**，实用性大降；
  - 概念 9「层积」：方块堆叠 + 硬色块撞色 + 时序母题（"图形太丑、配色很烂"）；
  - 概念 11「气脉流转」：点密度太低(约20采样点插值出大而空的场) + 被硬长方形框死。
  → 新红线：**信息载体须高密度离散（密集点阵/细密线网/大量小单元）或不用连续场；
     形态边界须自然（圆/放射/有机/全幅深底），勿硬长方形截断。**

---

## 5. 动效铁律（用户审美，强约束）

1. **创新第一 / 非大众化**——拒绝 SaaS 蓝白渐变 + 圆角卡片那套，要有辨识度。
2. **有意义 + 实用价值**——动效服务于学习闭环，不是装饰。
3. **现代感 / 艺术现代化**——但克制，零辉光零 bloom 优先。
4. **信息可视化优先**（见 §4）。
5. **真实操作驱动、确定可控、非游戏**：
   - 由用户真实操作（滚动/悬停/打开/聚焦/切换）持续驱动；
   - **确定可控**：不失控乱跑（自由流体式火球乱窜被否），也不是 idle 空浮动；
   - **非游戏**：拒绝问答/计分/输赢/抽测机制。
6. **落在真实界面**——看得见动效加在哪，不是独立 demo。
7. **图表本体 + 风格层**（形态优先于特效）——先把图表本体做对，再叠加风格。
8. **禁用软圆辉光、零 bloom**（克制）。

> 抽笺母题（抽笺 / 叠笺 / 考点星图 / 识海星砂）可作为落地母题；
> **每个动效必须有买点与价值闭环**（落点 + 钩子 + 学习价值 + 回传）。

---

## 6. 帧率无关动效

- 动效步进与刷新率**解耦**：60Hz 与 144Hz 下末值必须一致。
- 用固定时间步长累加，而非"每帧 +1"。
- 验收时可关自动帧循环、手动步进以做确定性断言（参考 Godot `set_process(false)` 后手动 `_process(dt)`）。

---

## 7. 自动化验收套路（headless 思路，C++ 可类比）

Godot 版用「引擎级 headless 探针」代替目测，思路可直接迁移到 C++（CI / 单元测试 / 渲染探针）：

1. **先过编译/语法全量检查**，再跑运行时探针。
2. **探针里避免裸引用全局单例**：用 `get_node_or_null("X")` 取得运行实例，绝不写裸 `X.xxx`；
   不给局部变量标死类型注解（会阻断对实例方法的动态调用）；状态枚举用数字字面量。
3. **日志写文件再读**，避免管道吞输出。
4. **良性报错判别**：Godot 4.7.x 退出期有 16 行良性 engine bug
   （`Unreferenced static string` / `NavMesh RID leak` / `PagedAllocator`），
   与项目代码无关。**勿为压制它去禁用插件或删配置**——彻底消除只能等引擎升级。
   C++ 同理：先区分"运行时真实错误"与"退出期/第三方库的无关诊断噪音"。

## 8. 表现层资产交付常见编译阻断（复刻时先查）

（Godot 专属，但反映"美术交付物 ≠ 软件"的通用坑：概念原型 ≠ 软件，资产 ≠ 设计）

1. 资源文件子资源 `id` 用旧版未引号（`id=StyleBoxFlat_X`）→ 须 `id="StyleBoxFlat_X"` + `SubResource("X")`。
2. `draw_rect(rect, filled, color, width)` 参数顺序写反（应为 `rect, color, filled, width`）。
3. 子类变量与基类同名重名 → 改名。
4. `var r := min(a,b) - k` 类型推断失败 → 显式标类型。
5. **红线自检**：表现层 grep `answer` 须零命中；只读取核心层烘焙的离线快照，不本地累加 mastery。

---

## 9. 概念原型管理（想法库纪律）

- 想法库（概念 8–12）**单独存档**，与软件工程隔离。
- **通过的配方 → 沉淀为正例**：概念 10 考点星图、概念 12 识海星砂（新基线）。
- **被否的 → 正式摒弃**：概念 8 弦、概念 9 层积、概念 11 气脉流转。
- **不要反复回退到被否版本**：v3/v4/v5 在卡片上反复堆风格层均失败，最终回退到 v2 基线。

---

## 10. 给 C++ 桌面端的落地清单（Checklist）

- [ ] 核心层持有全部业务状态与判分权；渲染层只持有快照。
- [ ] 题面不下发答案；作答上报 *selected*，核心层判 *correct*。
- [ ] 掌握度由核心层计算并下发；渲染层只读 `mastery`。
- [ ] 掌握度支持 `known` 反向衰减（遗忘曲线双向）。
- [ ] 先搭软件框架（splash→home→各业务页→GameSlot），再放游戏化。
- [ ] 视觉：浅色纸底 `#F6F2E9` + 青绿 `#268678` + 衬线标题/等宽数字 + 8px 栅格 + bloom≤0.3。
- [ ] 含数据的界面：坐标轴+刻度+标签+可读几何；框选聚合 / 悬停精确值。
- [ ] 动效：真实操作驱动、确定可控、非游戏、落真实界面、图表本体优先、零软圆辉光。
- [ ] 动效帧率无关（固定步长）。
- [ ] 自动化验收：编译全量检查 + 运行时探针（日志落盘），区分良性噪音与真实错误。
- [ ] 想法库与工程隔离；通过的配方沉淀，被否的摒弃，不回退。
